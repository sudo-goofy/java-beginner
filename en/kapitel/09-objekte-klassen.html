Classes & objects

A class is the blueprint. Objects are what gets built from it afterward, and only those can be used.

approx. 50 min

THE PROBLEM

Two zombies, each with a name and hunger. How do you keep the data together?

Horde.java

String name1 = "Zombiefelix";
int hunger1 = 7;
String name2 = "Mia";
int hunger2 = 3;
System.out.println(name1 + " has hunger " + hunger1);
System.out.println(name2 + " has hunger " + hunger1);
CONSOLE

Mia has hunger 7? Name and hunger belong together only through the number in the variable name, and nobody notices a wrong number.

Horde.java

class Zombie {
    String name;
    int hunger;

    Zombie(String name, int hunger) {
        this.name = name;
        this.hunger = hunger;
    }

    void report() {
        System.out.println(name + " has hunger " + hunger);
    }
}

public class Horde {

    public static void main(String[] args) {
        Zombie felix = new Zombie("Zombiefelix", 7);
        Zombie mia = new Zombie("Mia", 3);
        felix.report();
        mia.report();
    }

}
CONSOLE

Each object carries its own name and its own hunger. This chapter shows what a class is and how you create objects.

9.1 Class and object

Programs model the real world: customers, orders, traffic lights, zombies. It does not consist of single ints and Strings, but of things with several properties. A class combines these properties into a blueprint.

  • A class is a blueprint: It describes which properties (attributes) and abilities (methods) a kind of thing has. For example: “Every zombie has a name, color, and mood.”
  • An object is a concrete instance built from this blueprint: this one zombie named Zombiefelix, orange, hungry.

Like cookie cutters (class) and cookies (objects): one cutter, any number of cookies, each decorated differently.

Explained differently: the formoptional

An empty registration form at the Zombie Defense Center has preprinted fields: Name: ___, Color: ___, Mood: ___. It is not a zombie yet, but it says what information there is about a zombie.

  • Class = the empty blank form (defines the fields)
  • Object = a filled-out copy (Name: Zombiefelix, Color: orange, …)
  • new = “copy the blank form and fill it out, please!”

There can be hundreds of filled-out forms from the same blank form, each with different information.

STRUCTURE · CLICK A PART

public class class name {
    type attribute;
    type attribute;
}

class name variable = new class name();
variable.attribute = value;

The attributes are in the class, but not in any method. The two lower lines are in the main of another class.

Class name: starts with an uppercase letter, such as Zombie, and the file has the same name: Zombie.java. It appears twice in the lower line: at the front as the type of the variable, after new as the class an object is created from.
Type: the data type of the attribute, such as String for text or int for integers. It determines which values the attribute can hold.
Attribute: a property that every object of the class has, written in lowercase, such as name or mood. Each object has its own value for it. As long as you do not set one, a String attribute holds null.
Variable: stores a reference to the new object, such as felix. Its type is the class. You reach the object through this name afterward, as in the last line before the dot.
new creates a new object of the class, with its own values for all attributes. The parentheses after it are part of it: new Zombie(). Using new twice gives two independent objects.
The dot operator accesses an attribute of a specific object: felix.name means “the attribute name of felix”. On the left of the = you write a value into it this way, with System.out.println(felix.name); you read it out.
Value: what is written into the attribute. It must match the type: "Zombiefelix" in quotation marks for a String, 3 without quotation marks for an int.

The simplest class in the world

Totally minimal: a class that only describes what every zombie has:

Zombie.java: version 1, attributes only

public class Zombie {

    // Attributes: what does every zombie have?
    String name;
    String color;
    String mood;

}

That is it: a class with only attributes, no main. You cannot run it. It is used by an executable class with main:

ZombieApocalypse.java, the executable class

public class ZombieApocalypse {

    public static void main(String[] args) {
        Zombie felix = new Zombie();     // new creates an object of the class

        felix.name = "Zombiefelix";      // dot operator: fill in the attribute
        felix.color = "orange";
        felix.mood = "hungry";

        System.out.println(felix.name);   // … and read it out
        System.out.println(felix.color);
    }

}
CONSOLE

LINE BY LINE

String name;an attribute: Every zombie gets its own field name. Nothing is in it yet.
Zombie felix = new Zombie();new creates an object of the class Zombie. It can be reached through the variable felix, whose type is the class.
felix.name = "Zombiefelix";the dot operator: The attribute name of felix gets a value.
System.out.println(felix.name);reads the attribute back through the dot and prints Zombiefelix.

Attributes without a value

You first, then Java

Version 1 has a catch. What happens if you forget to fill them in?

ZombieApocalypse.java: oops

Zombie mia = new Zombie();      // Object built …
                              // … but nobody set the attributes!
System.out.println(mia.name); //  ???
CONSOLE: what will it print?

null means “nothing there”. The object mia exists, but nobody has set its attributes. Objects with unset attributes are one of the most common sources of errors:

  • Nothing crashes yet, println(mia.name) just shows null.
  • If you do something with the name, such as mia.name.length(), Java throws the notorious NullPointerException (Panic glossary).

Remember this

The dot operator means “of”: felix.name = “the name of felix”. Reading and writing both go through the dot.

9.2 Constructors

It would be better if you could not create an object without values in the first place. That is what the constructor is for: It runs on every new and defines which values you must provide.

STRUCTURE · CLICK A PART

public class name(type parameter, …) {
    this.attribute = parameter;
}

class name variable = new class name(value, …);

The constructor has exactly the same name as the class and no return type, not even void. new calls it and passes the values to it in the same order.

Class name: At the top, it is the name of the constructor, such as public Zombie(…) in the class Zombie. At the bottom, it appears as the type of the variable and after new. If you write void before the constructor, it becomes an ordinary method, and the compiler reports an error for new Zombie("Mia", …).
Type: the data type of the parameter, usually the same as for the attribute it fills: String name for the attribute String name;.
Parameter: receives a value that the call with new passes along, and is usually named like the attribute, such as name. On the right of the =, its value is written into the attribute. Multiple parameters are separated by a comma, and each one is mandatory.
this stands for the object that is currently being created: this.name is its attribute, name alone is the parameter. If you leave out this., name = name; assigns the parameter to itself, and the attribute stays null, without the compiler reporting anything.
Attribute: one of the attributes declared at the top of the class. The constructor gives it its starting value, one line like this for each attribute.
Variable: stores the reference to the new object, such as felix. Its type is the class.
Values: The first goes to the first parameter, the second to the second, and each must match the type of its parameter: new Zombie("Mia", "gray", "relaxed"). If this is the only constructor, the compiler reports an error for new Zombie() without values.

Zombie.java: version 2, with constructor

public class Zombie {

    String name;
    String color;
    String mood;

    // The constructor: WITHOUT these three values there is no zombie!
    public Zombie(String name, String color, String mood) {
        this.name = name;      // "MY name = the value that came in"
        this.color = color;
        this.mood = mood;
    }

}

LINE BY LINE

public Zombie(String name, …)the constructor: has the same name as the class, no return type. Its parameters are the mandatory values.
this.name = name;this = “this object here”. this.name is the attribute of this object, name is the parameter, that is, the value that was passed in.
new Zombie("Mia", …)calls the constructor. “Mia” ends up in name, “gray” in color, “relaxed” in mood.
// Zombie geist = new Zombie();is commented out, because without the three mandatory values the line would be a compiler error.

ZombieApocalypse.java: with mandatory values

public class ZombieApocalypse {

    public static void main(String[] args) {
        Zombie felix = new Zombie("Zombiefelix", "orange", "hungry");
        Zombie mia   = new Zombie("Mia", "gray", "relaxed");

        // Zombie geist = new Zombie();   Compiler error! Mandatory fields missing.

        System.out.println(felix.name);
        System.out.println(mia.name);
    }

}
CONSOLE

Remember this

Three terms, one sentence: new creates the object and calls the constructor, which sets the attributes right away, and the dot operator (felix.name) then accesses attributes and methods. That is 80 % of object-oriented programming. Honestly.

Level-up: Why exactly the “this” in the constructor?optional

this.name = name; looks like saying the same thing twice. Parameter and attribute are both called name, and this (“this object here”) resolves the confusion:

this explained

this.name = name;
// ^^^^^^^   ^^^^
// Attribute  Parameter (the value that came in)
// "MY name should be the name that was passed in"

Without this., the parameter with the same name shadows the attribute (scope, Chapter 4). name = name; then assigns the parameter to itself, and the attribute stays untouched. The compiler reports nothing, since the line is formally correct.

You could name the parameter differently and do without this, but the this notation is the standard.

Level-up: Overloaded constructorsoptional

A class may have several constructors if the parameter lists differ: Overloading.

Zombie.java (excerpt)

public Zombie(String name, String color, String mood) {
    this.name = name;
    this.color = color;
    this.mood = mood;
}

public Zombie(String name) {              // Short version!
    this.name = name;
    this.color = "gray";                  // Default values
    this.mood = "relaxed";
}

Java recognizes from the arguments which constructor is meant: new Zombie("Mia") → short version, new Zombie("Zombiefelix", "orange", "hungry") → full version.

9.3 Object methods

In Chapter 4, your methods stood next to the main. Usually, though, they belong in the class of the objects: There they can use the object's attributes and describe what every zombie can do.

STRUCTURE · CLICK A PART

public class class name {
    return type method(Parameter) {
        statements that use the attributes
    }
}

variable.method(arguments);

The method is called on an object, with the dot operator: first the object, then the name of the method.

Class name: the class the method belongs to, such as Zombie. The method is in the class body next to attributes and constructor, never inside another method.
Return type: the type of the value the method returns with return, or void if it returns nothing: void groan(). There is no static in front of it here, because the method belongs to each individual object.
Method name: lowercase, usually a verb, such as groan. The call below uses the same name, followed by parentheses, even if they stay empty.
Parameters: values the method additionally needs when it is called, each with a type, such as double amount. The object's attributes do not belong here, the method already knows them. If it needs nothing, the parentheses stay empty.
Statements: the method body. Here you use the attributes directly by their name, without a dot: System.out.println(name + " groans: Grrr!");. It always means the attribute of the object the method is currently called on.
Variable: the reference to the object the method is called on. For felix.groan(), name in the body is “Zombiefelix”, for mia.groan() it is “Mia”.
Arguments: the values for the parameters, in the same order and with matching types, such as account.deposit(20). Without parameters the parentheses stay empty: felix.groan();.

Zombie.java (excerpt) + call

public class Zombie {

    String name;
    // … constructor as above …

    void groan() {                  // NO static, the method belongs to the object!
        System.out.println(name + " groans: Grrr!");
    }

}

// Call via the dot operator, "groan of felix":
felix.groan();     //  Zombiefelix groans: Grrr!
mia.groan();       //  Mia groans: Grrr!

LINE BY LINE

void groan()a method in the class Zombie, without static and without parameters.
name + " groans: Grrr!"uses the attribute name of the object the method is currently called on.
felix.groan();read as “groan of felix”: So here name is “Zombiefelix”.
mia.groan();the same method on a different object, so with “Mia”.

Remember this

New compared to Chapter 4:

  • No static: The method belongs to each individual object, not to the class as a whole.
  • No name parameter: Every zombie knows its own name. Same call, personal answer.

9.4 Encapsulation: access modifiers, getters and setters

So far, anyone from outside could set felix.mood = "exploding", even if that is not a valid mood. The solution is called encapsulation: make attributes private, allow access only through methods.

Two keywords control who may access what:

  • private: Only code in the class itself can get at it.
  • public: Usable from anywhere.
  • From outside, therefore, access is only possible through methods: Getters return a value, setters change it and first check whether the new value is valid.

STRUCTURE · CLICK A PART

private type attribute;

public type getattribute() {
    return attribute;
}

public void change(type value) {
    if (value is valid) {
        attribute = new value;
    }
}

The getter is named like the attribute, with get in front. The method that changes something checks first and only changes it if everything is fine.

private: Only code in the same class can get at the attribute. If another class writes account.balance, the compiler reports an error. From outside, access is only possible through the methods below.
Type: appears three times and is the same each time, such as double: as the type of the attribute, as the return type of the getter, and as the type of the parameter.
Attribute: the name of the protected attribute, such as balance. Inside the class, the methods use it directly by its name, without a dot.
public: The method can be called from anywhere, including from other classes, such as account.getBalance() in the main. All access from outside goes through these methods.
Getter: After get comes the attribute name with a capital first letter, balance becomes getBalance(). It has no parameters, returns the value of the attribute with return, and changes nothing.
Name of the changing method: says what it does, such as deposit. If it sets an attribute directly to a new value, it is usually called set plus the attribute name, such as setMood, and it is called a setter. Its return type is void.
Value and new value: The parameter brings along the desired value, such as double amount. Below, it becomes the new value of the attribute, either taken over directly or used in a calculation: balance = balance + amount;.
The check: a condition that catches invalid values, such as amount > 0. If it is false, the block is skipped, and the attribute stays as it was. No semicolon directly after if (…), otherwise the block always runs.

Account.java, well encapsulated

public class Account {

    private double balance;          // private: accessible only inside Account

    public double getBalance() {     // Getter: delivers the value to the outside
        return balance;
    }

    public void deposit(double amount) {   // Request a change
        if (amount > 0) {                    // IF the amount is okay …
            balance = balance + amount;          // … THEN it is changed
        }
    }

}

LINE BY LINE

private double balance;private: Only code in the class Account itself can get at balance.
public double getBalance()the getter: returns the balance, but changes nothing.
public void deposit(double amount)changes the balance. From outside, this is the only way to change the balance.
if (amount > 0)the check: Only a positive amount gets through. This is the if from Chapter 6 in its most important use.

Remember this

Attributes private, access only through methods. The method checks the new value and catches invalid values before it changes an attribute.

Level-up: Why bother with getters and setters?optional

Three reasons from real projects:

  1. Validation: The setter can reject nonsense (negative deposit, age = -5, mood = “exploding”).
  2. Control: You can make attributes read-only: getter yes, setter no. Unchangeable from outside.
  3. Flexibility: You can rebuild the inside of the class later. Whoever uses it notices nothing and keeps calling only getBalance().

In short: Without encapsulation, any class may change an attribute directly. With encapsulation, every change goes through a method that checks.

9.5 Reference variables

In Chapter 3 it said: “A variable is a box with a value inside.” For numbers, that is true. For objects, the variable does not hold the zombie, only a reference to it. In a memory diagram, it is drawn as an arrow. The zombie itself lives in the heap, the area of main memory where Java creates objects.

STRUCTURE · CLICK A PART

Class b = a;
Class c = new Class(values);

Both lines store a reference in a variable, but only the second one creates an object. So references can be copied.

Class as type: such as Zombie. A variable of this type never stores the object itself, but a reference to an object of the class. The object lives in the heap.
b gets a copy of the reference from a. After that, a and b refer to the same object: If you change b.mood, you read the new value through a.mood.
a is a variable that already contains a reference, such as felix. It stays unchanged itself, only its reference is copied.
c gets the reference to the newly created object. Even if it has the same values as the object of a, c == a evaluates to false, because == compares references for objects, not contents. That is why you compare Strings with .equals().
new creates a new object in the heap and returns the reference to it. Only new creates objects, an assignment like in the first line never does.
Values: the arguments for the constructor, in the order of its parameters, such as new Zombie("Mia", "gray", "relaxed").

The twin experiment

Run the three lines one after another and keep an eye on the zombie.

felix
twin

  • mood = "relaxed"

Start: There is ONE zombie and ONE reference to it (variable felix).

LINE BY LINE

Zombie twin = felix;copies the reference from felix into the variable twin. There is no new, so no second zombie is created either.
twin.mood = "offended";follows the reference to the object in the heap and changes the mood there.
felix.moodfollows the reference in felix, arrives at the same object and reads the mood there.

Remember this

The punchline:

  • twin was never a second zombie, just a second reference to the same zombie. Whatever you change through twin also changes for felix.
  • This solves the riddle from Chapter 6: A String is an object, too. With "yes" == answer, == only checks whether two references point to the same object, not whether the text is equal. That is why you should always compare texts with .equals().

9.6 UML class diagram

In projects and exams, classes are sketched as a UML class diagram: a box with three areas for name, attributes, and methods. That is how a class looks on paper before the first line of Java is written.

STRUCTURE · CLICK A PART

class name
- attribute: type
+ class name(parameter: type)
+ method(parameter: type): return type

- means private, + means public. Unlike in Java, the type comes after the name, following a colon.

Class name: stands alone in the top area, such as Zombie. If it shows up again in the list below, that is the constructor: In UML, as in Java, it has no return type.
Visibility: Every line below the class name starts with its symbol. Private attributes and public methods are the usual choice, that is, the encapsulation from 9.4. In Chapter 10, # for protected is added.
Attribute: in the middle area, one per line. - name: String becomes private String name; in Java.
Type: the data type, after the name in UML. When converting to Java, it moves to the front: age: int becomes int age.
Parameter: in the parentheses, several separated by commas, each with its type after it. (name: String, age: int) becomes (String name, int age) in Java.
Method name: lowercase, in the bottom area below the constructor, one method per line. The parentheses are there even if there are no parameters: groan().
Return type: at the very end, after the colon behind the parenthesis. In Java it comes before the name: + groan(): void becomes public void groan().
Zombie
  • - name: String
  • - color: String
  • - mood: String
  • + Zombie(name, color, mood)
  • + groan(): void

LINE BY LINE

- name: Stringa private attribute, in Java private String name;.
+ Zombie(name, color, mood)the constructor: public, with three parameters and no return type.
+ groan(): voida public method without parameters that returns nothing. In Java, void comes before the name.

Remember this

Three areas: name, attributes, methods. - means private, + means public: the encapsulation from the Account example.

Level-up: When classes know each otheroptional
  • When classes know each other (a person has a zombie), a line connects them, an association.
  • Numbers on the line are called “cardinalities”: 1, 0..* for one person with 0 to many zombies.

That's enough for now

  • Class = blueprint, object = concrete instance. Every new creates a new, independent one.
  • new Zombie(…) calls the constructor: same name as the class, no return type. this.name means the attribute.
  • felix.name = “name of felix”: The dot accesses attributes and methods.
  • Methods without static are in the class and use the attributes of the object they are called on.
  • private + getter/setter protect the data (encapsulation). In UML: - private, + public.
  • A variable holds only a reference: b = a copies the reference, not the object. That is why you compare Strings with .equals().

Checkpoint

6 questions about classes and objects.

1. Class and object, what is true?

One class, any number of objects, and each has its own attribute values.

2. What happens with Zombie mia = new Zombie("Mia", "gray", "relaxed");?

new creates the object, the constructor sets its attributes. From then on, the variable mia holds the reference to this object.

3. How do you read felix.mood?

The dot operator = “of”. With it you access attributes and methods of an object.

4. How do you recognize a constructor in a class?

Class Zombie → constructor public Zombie(…). No void, no int in front, constructors always “deliver” the new object.

5. Why should balance in Account be private?

Encapsulation: The method checks every change and rejects, for example, negative deposits. Direct access = no control.

6. After Zombie a = felix; you set a.mood = "wild";, what is felix.mood?

The twin experiment: One zombie, two references. What you change through one variable, you also see through the other.
