Inheritance & abstract classes

Three classes that are eighty percent identical: That is no coincidence, but a hint.

approx. 40 min

THE PROBLEM

Circle and Rectangle can be moved. The code for that is copied. Where do the two end up?

Moving.java

class Circle {
    int x = 10, y = 10;
    void move(int dx, int dy) { x = x + dx; y = y + dy; }
}

class Rectangle {
    int x = 10, y = 10;
    void move(int dx, int dy) { x = x + dx; y = y + dx; }
}

public class Moving {

    public static void main(String[] args) {
        Circle k = new Circle();
        Rectangle r = new Rectangle();
        k.move(5, 0);
        r.move(5, 0);
        System.out.println("Circle at (" + k.x + ", " + k.y + ")");
        System.out.println("Rectangle at (" + r.x + ", " + r.y + ")");
    }

}
CONSOLE

The Rectangle has slid off diagonally: The copied method has dx instead of dy. The same code appears twice, so it can also be wrong in two places.

Moving.java

class Shape {
    int x = 10, y = 10;
    void move(int dx, int dy) { x = x + dx; y = y + dy; }
}

class Circle extends Shape { }

class Rectangle extends Shape { }

public class Moving {

    public static void main(String[] args) {
        Circle k = new Circle();
        Rectangle r = new Rectangle();
        k.move(5, 0);
        r.move(5, 0);
        System.out.println("Circle at (" + k.x + ", " + k.y + ")");
        System.out.println("Rectangle at (" + r.x + ", " + r.y + ")");
    }

}
CONSOLE

What both have in common is written once, in the superclass Shape. Circle and Rectangle inherit it. This chapter shows how inheritance works.

10.1 Inheritance with extends

A drawing program has the classes Circle and Rectangle. Both have a position (x, y), and both can be moved and drawn. Instead of writing everything twice, what they have in common goes into a superclass (also called “parent class”), and the subclasses (also called “child classes”) inherit it.

STRUCTURE · CLICK A PART

public class subclass extends superclass {
    only what the subclass adds
}

extends means “inherits from”. What the superclass has, the subclass has too, without declaring it itself.

Subclass: the new, more specific class, such as Circle. An object of the subclass is also an object of the superclass: Every Circle is a Shape.
extends connects the subclass to its superclass. Exactly one class name follows it, because Java does not allow several superclasses at once.
Superclass: the more general class with what all subclasses have in common, such as Shape with x, y, and move(). If you change something there, the change applies to all subclasses.
Class body of the subclass: only what is added: its own attributes like private int radius;, its own constructor, and its own versions of methods. You do not declare inherited attributes like x again here.

Shape.java + Circle.java

public abstract class Shape {              // the superclass
    protected int x;                        // protected: visible in subclasses too
    protected int y;

    public void move(int dx, int dy) {
        x = x + dx;
        y = y + dy;
    }

    public abstract void draw();         // Every subclass must override draw().
}

public class Circle extends Shape {          // extends = "inherits from"
    private int radius;

    public Circle(int x, int y, int radius) {
        this.x = x;                          // x and y? Inherited! Never declared here.
        this.y = y;
        this.radius = radius;
    }

    @Override
    public void draw() {
        System.out.println(" Circle at (" + x + "," + y + "), r=" + radius);
    }
}

LINE BY LINE

protected int x;The position is written only once, in the superclass. protected makes it visible to the subclasses too.
public void move(…)Moving is also written only in Shape. Every Circle can still do it, because it inherits it.
public abstract void draw();Every Shape can draw itself, but how is decided only by the subclass.
class Circle extends ShapeCircle inherits everything from Shape and writes only what makes it special.
private int radius;what is its own: Only the Circle has a radius.
this.x = x;x and y are inherited, never declared in Circle. Circle sets them by hand here, because protected allows it. If the superclass has its own constructor, super(…) takes care of that, as in all the following examples.
@OverrideHere Circle fills in its own draw().

Remember this

  • Generalization: combine upward. Specialization: refine downward.
  • The inheritance arrow in UML points to the superclass: Circle → Shape.

10.2 super, protected, and abstract classes

The superclass does not just pass on attributes. Its constructor sets up its part of the object (super), it can open up attributes to its subclasses (protected), and it may be a pure concept that only the subclasses fill in (abstract).

STRUCTURE · CLICK A PART

public abstract class superclass {
    public abstract type method();
}

public class subclass extends superclass {
    public subclass(Parameter) {
        super(arguments);
    }

    @Override
    public type method() {
        how the subclass does it
    }
}

super(…) goes on the first line of the subclass constructor and calls the superclass constructor. An abstract method has no body, only a semicolon.

abstract before class: There are no objects of this class, and for new Shape() the compiler reports an error. abstract before a method: It consists only of the method header, and every non-abstract subclass must override it. A class with an abstract method must itself be abstract.
Superclass: the general class, such as Zombie. It specifies what all subclasses have in common, here also that every subclass has the method. In the subclass, its name goes after extends.
Return type and method name: In the subclass they are exactly the same as in the abstract method, and so are the parameters, such as public void groan(). Only then does the subclass override the method of the superclass.
Subclass: the specific class, such as Walker. Its constructor has exactly the same name as the class and no return type: public Walker(…).
Parameters: all values a new object of the subclass needs, including those for the inherited part: public Walker(String name, int age).
super(…) passes the arguments on to the superclass constructor, which uses them to set the inherited attributes: super(name, age);. The number and types must match that constructor. If the superclass has only constructors with parameters and super(…) is missing, the compiler reports an error.
@Override goes directly above a method that overrides a method of the superclass. The compiler checks whether there is a matching one: For a typo like groans() it reports an error instead of quietly creating a new method.
Method body: exactly how this subclass carries out the method, such as System.out.println(name + " groans: Grrr!");. Each subclass writes its own version here.
  • extends: “inherits from”. The subclass has everything from the superclass, plus its own. Only one superclass per class.
  • protected: level between private and public. The class itself and its subclasses may access it. (Classes in the same package may access it too, so without packages of your own, that means your whole project.)
  • super: With super(…), the constructor of the subclass calls the constructor of the superclass. That sets up the inherited part of the object. With super.method() you call the version of the superclass.
  • abstract: For classes: concept only, cannot be instantiated (new Shape() does not compile). For methods: no body, only a semicolon, every subclass must implement it.
  • @Override: marks a method that deliberately overrides a method of the superclass. The compiler checks whether there is a matching method there.

Why abstract? What would new Shape() be: round, angular, both? There is no “Shape as such”, only concrete shapes. abstract says: This class is only a concept. Test it below.

You first, then Java

What appears first for new Walker("Mia", 2);: the message from the superclass (Zombie) or the one from the subclass (Walker)? Both constructors report in with println. Predict the order:

Baureihenfolge.java (excerpt)

public Zombie(String name, int age) {
    this.name = name;
    this.age = age;
    System.out.println("Zombie part built");
}

    super(name, age);                       //  the crucial line
    System.out.println("Walker part built");

// in main:
new Walker("Mia", 2);
CONSOLE
Answer: run it first, then expand it!

First the superclass (Zombie part built), then the subclass: super(…) is on the first line and immediately calls the constructor of the superclass. The inherited part of the object is set up first.

10.3 Polymorphism and overriding

Same call, fitting answer per object. That is why loops over the supertype also work with classes that do not exist yet.

STRUCTURE · CLICK A PART

superclass[] name = { new subclass(…), new another subclass(…) };

for (superclass element : name) {
    element.method();
}

The array has the type of the superclass, its elements are objects of the subclasses. Each one brings its own version of the method.

Superclass as type: Up front the array has the type Shape[], in the loop the variable has the type Shape. A variable of the superclass type can store a reference to an object of any subclass.
Name of the array: freely chosen, such as picture. After the colon of the loop comes the same name: The loop iterates over exactly this array.
Objects of the subclasses: Each new creates an object of a concrete subclass, such as new Circle(60, 45, 30) or new Rectangle(150, 25, 90, 55). new Shape(…) does not work, because there are no objects of an abstract class.
Loop variable: In each iteration it holds the reference to the next element, such as f. Its type stays the superclass, even when it is a Circle's turn.
The colon turns this into a for-each loop, read it as “in”: for each Shape f in picture. The loop takes each element in turn, with no index at all.
Method: It must be declared in the superclass, otherwise the compiler reports an error at f.draw(), because it only knows the type Shape. Which version runs is decided only at run time, by the actual object: for the Circle, the one from Circle.

The finale: polymorphism live

An array full of Shape objects (works because Circle and Rectangle both “are a Shape”). All of them get the same call draw(), and each object answers in its own way. That is polymorphism (“many forms”).

Leinwand.java

Shape[] picture = { new Circle(60, 45, 30),
                 new Rectangle(150, 25, 90, 55),
                 new Circle(290, 50, 20) };

for (Shape f : picture) {
    f.draw();     // same call, three different results!
}

LINE BY LINE

Shape[] picture = { … };an array of the superclass type. Any object that is a Shape may go in: Circle and Rectangle objects.
for (Shape f : picture)goes through all elements. For the loop, f is simply a Shape.
f.draw();the same call for all of them. A Circle draws itself as a circle, a Rectangle as a rectangle.

Remember this

  • The loop above does not know which Shape objects are in the array. It does not need to.
  • If Triangle extends Shape is added, it runs unchanged: The Triangle draws itself.
  • The principle: Program against the general (Shape), not against the specific (Circle). That way a program stays extensible without touching old code.

In real projects that means: “feature in 2 hours” instead of “feature in 2 weeks”.

Level-up: How do I know my code is correct? (Mini preview: tests)optional

Pros do not click through their program by hand a hundred times. They write tests, small programs that check the program itself. In Java with JUnit:

FigurTest.java

@Test
void moveAddsCorrectly() {
    Circle k = new Circle(10, 10, 5);
    k.move(5, -3);
    assertEquals(15, k.x);   // expect: x is now 15
    assertEquals(7, k.y);    // expect: y is now 7 (protected: the test is in the same package)
}

Green: The logic is correct. Red: You know right away where the problem is. Two kinds of tests:

  • Black-box tests: look only at input and output, the inner workings do not matter.
  • White-box tests: deliberately check all code paths.

Checkpoint

5 questions on inheritance and polymorphism.

1. public class Circle extends Shape: What does that mean?

extends = “inherits from”. The direction: The subclass (Circle) comes first, the superclass (Shape) comes last.

2. Why does new Shape() fail?

abstract prevents instantiation. You can certainly create objects of normal (non-abstract) superclasses.

3. What does protected do?

The level between the two: stricter than public, looser than private. Suitable for attributes that subclasses need (like x and y in Shape).

4. Circle and Rectangle each have their own draw(). In the loop, f.draw() is called and each object does its own thing. What is that called?

Polymorphism = many forms: same method call, object-specific behavior. The finale of the basic OOP ideas.

5. Why does the constructor of a subclass call super(x, y)?

super(…) calls the constructor of the superclass. It sets x and y, and the constructor of the subclass only handles radius & co.
