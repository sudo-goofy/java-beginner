2.1 Structure of a Java program

Every Java program has the same skeleton: a class on the outside, inside it the main method, where the program starts. What it should do is written as a statement in main.

STRUCTURE · CLICK A PART

public class {ClassName} {

    public static void main(String[] args) {
        {statements}
    }

}

The file is named exactly like the class, so for HelloWorld it is HelloWorld.java. The rest of the skeleton is the same every time.

public class introduces the class. Every Java program lives in a class. public means: reachable from anywhere, including the JVM.
Class name: freely chosen, starts with an uppercase letter, no spaces, for example HelloWorld. The file must have exactly the same name: HelloWorld.java, otherwise the compiler reports an error.
The outer braces mark the beginning and end of the class. Curly braces always come in pairs: every { has a matching }.
The main method: This is where the JVM starts the program. The line is the same every time, memorize it or let the IDE fill it in. What the individual words mean is explained in the Level-up further down.
The inner braces mark the beginning and end of the main method. Everything in between runs at startup.
Statements: what the program should do, from top to bottom, each with ; at the end. For example System.out.println("Hello World!");

HelloWorld.java

public class HelloWorld {

    public static void main(String[] args) {
        System.out.println("Hello World!");
    }

}
CONSOLE

Seven lines for one sentence? Yes. Java is formal, like an email that begins with “Dear Sir or Madam” just to say “ok”. But every line has a job:

LINE BY LINE

public class HelloWorldEvery Java program lives in a class, here named HelloWorld. The file must then be called HelloWorld.java.
public static void main(…)The main method, the entry point: The JVM looks for exactly this method and starts execution there. Just write it down from memory, the pros do that too.
System.out.println("…")The output: “System, print a line (println) on the output channel (out).” Text is always in double quotes.
;The semicolon ends every statement, like the period at the end of a sentence.
{ }Curly braces mark the beginning and end of a block, here of the class and the main method. Always in pairs.

Remember this

A Java program lives in a class and starts in the main method. The file is named like the class: HelloWorld.java.

Level-up: What does “public static void main” actually mean?optional

Every word has a fixed meaning:

  • public: callable from anywhere, including by the JVM at startup
  • static: belongs to the class itself, no object needed (Chapter 4 & 9)
  • void: the method returns nothing (Chapter 4)
  • main: the fixed name the JVM looks for at startup
  • String[] args: texts you can pass in at startup, as an array (Chapter 8)

Just write it down from memory. Pros let the IDE complete it automatically.

2.2 Syntax rules: semicolon, braces, capitalization

At the beginning, almost all error messages have the same three causes. If you know these three rules, you recognize most errors before the compiler reports them.

Remember this

  1. Every statement ends with a semicolon ;, forget it = error.
  2. Capitalization matters. System works, system is unknown to Java.
  3. Curly braces { } always come in pairs. Every opened brace wants to be closed again.

2.3 Identifiers and naming conventions

The compiler translates every permitted name. For people who read the code, that is not enough. That is why there are conventions: rules without an error message, but binding all the same.

WhatHowExample
Classfirst letter uppercase, every further word too (PascalCase) HelloWorld, ZombieApocalypse
Variable, methodfirst letter lowercase, every further word uppercase (camelCase) age, maxWeight, makeSound()
Constantall uppercase, words separated by underscores MAX_RESIDENTS, VAT

A constant must never change again, recognizable by the final in front: static final double VAT = 0.19;. More on static and final in Chapter 4, the uppercase spelling applies from now on.

Remember this

For classes it is more than a convention: The file is named exactly like the public class in it. HelloWorld lives in HelloWorld.java, uppercase and lowercase included. Renamed the class, forgot the file? Then the error message sounds like something completely different.

And: The name says what is inside. int a is allowed and still wrong as soon as someone else reads the code, your future self included.

2.4 Output, comments, and escape sequences

println prints a whole line. With print you assemble a line from several pieces, with special characters you bring line breaks and quotation marks into the middle of a text, and comments are notes that Java skips.

STRUCTURE · CLICK A PART

System.out.println(what gets printed);
System.out.print(what gets printed);

println stands for “print line”: print, then line break. print() without the “ln” leaves out the line break, the next output follows directly after it.

System.out is the standard output channel: the console. Uppercase S, otherwise the compiler does not know the name.
println (“print line”) prints and ends the line. The next output starts on a new line.
print prints without ending the line. The next output follows directly after it.
What gets printed: a text in double quotes like "Hello", a number like 42, or a calculation like 1 + 1. Text appears exactly as it stands between the quotes.
The semicolon ends the statement. If it is missing, the compiler reports ';' expected.

The computer works stubbornly from top to bottom. The outputs come exactly in this order:

DayPlan.java

public class DayPlan {

    public static void main(String[] args) {
        System.out.println("Line 1: Make coffee");
        System.out.println("Line 2: Write code");
        System.out.println("Line 3: Be puzzled");
        System.out.println("Line 4: Refill coffee");
    }

}

LINE BY LINE

System.out.print("Java");prints Java. No line break: the next output lands on the same line.
System.out.print("Script?");sticks directly behind it. Now the line contains JavaScript?.
System.out.println();prints no text, only the line break.
System.out.println("No.");therefore appears on the second line and then breaks the line itself.
Level-up: Special characters in texts (escape sequences)optional

Some characters do not fit directly into a String. That is what the backslash \ is for:

  • \n: line break in the middle of the text
  • \": a quotation mark in the text (otherwise the compiler thinks the String ends there)
  • \\: a real backslash

Escape.java (excerpt)

System.out.println("He said: \"Java is fun\"\nHonestly.");
System.out.println("Path: C:\\Program Files\\Java");
CONSOLE
Level-up: Comments: notes that Java skipsoptional

With // you write notes for humans only. Java ignores them completely:

Kommentare.java (excerpt)

// This is a comment. Java acts as if it were air.
System.out.println("I am code.");    // works after a statement too

/* And this is how you comment
   several lines at once. */
System.out.println("Me too.");
CONSOLE: what appears, what does not?

Few but good comments: they explain the why, not the obvious.

Remember this

print sticks, println breaks the line. Comments (//) are skipped by the compiler. Special characters in text start with a backslash: \n for a line break, \" for a quotation mark.

Exercise 2.4.1: Output workshop

Nine statements one below the other in one main. Write down the complete console output before you run it. Where does a line break occur, where not?

Output.java

public class Output {

    public static void main(String[] args) {
        System.out.println("Hello");
        System.out.print("Hello");
        System.out.println("A" + "B");
        System.out.println(1 + 2);
        System.out.println("1" + 2);
        System.out.println("Line1\nLine2");
        System.out.println("He said \"Hello\".");
        System.out.println();
        System.out.println("End");
    }

}
CONSOLE
The three spots where it gets stuck
  • Line 2 makes no line break. print without the “ln”, so the AB from line 3 sits directly behind it: HelloAB.
  • 1 + 2 calculates, "1" + 2 concatenates. As soon as a String is involved, + no longer adds, it concatenates.
  • \n and \" are escape sequences. One makes a line break, the other a quotation mark, both in the text.

The second-to-last line really is empty: println() without text only prints the line break.

That's enough for now

  • A Java program lives in a class and starts in the main method.
  • System.out.println("…") prints text. print sticks, println breaks the line.
  • 90% of beginner mistakes: forgot a semicolon, mixed up uppercase and lowercase, left a brace unclosed.
  • Classes in PascalCase, variables in camelCase, constants all uppercase (VAT).
  • The file is named like the class: HelloWorld.java.
  • Comments (//) are skipped by the compiler. Special characters in text: \n, \".

Checkpoint

4 questions about class, main, and output.

1. Where does every Java program start?

At startup, the JVM always looks for exactly public static void main(String[] args). No main, no start.

2. What is wrong with this line? system.out.println("Hi");

Java strictly distinguishes between uppercase and lowercase. System is a class, Java does not know system.

3. What does the ; at the end of the line do?

Without a semicolon the compiler does not know where the statement ends. The caret ^ in the message points directly behind the last character of the line where it is missing.

4. What is the difference between print() and println()?

“ln” = line. println jumps to the next line afterwards, print stays on the same line.
