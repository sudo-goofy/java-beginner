Chapter 5 of 11 · Other people's methods and the Scanner

Strings & input

Up to here you have built methods. Now you use ready-made ones and, for the first time, bring a value from outside into the program.

approx. 40 min

THE PROBLEM

The program is supposed to greet everyone sitting in front of it. Who does it greet?

Greeting.java

String name = "Aylin";
System.out.println("Hello " + name + "!");
CONSOLE

It always greets Aylin, no matter who is sitting in front of it. The name is fixed in the code.

Greeting.java

import java.util.Scanner;

public class Greeting {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        System.out.println("What is your name?");
        String name = keyboard.nextLine();
        System.out.println("Hello " + name + "!");
    }

}
CONSOLE

Now the program asks, and the name comes from the keyboard (“Mia” was typed here). This chapter shows how input works and how you prepare texts.

In this chapter

After this chapter you can

5.1 Methods of the String class

Most methods you will ever use were written by someone else. A few are built into every String: They count characters, remove spaces, and replace text, without you writing a single line of it yourself.

STRUCTURE · CLICK A PART

text.method(arguments)
text.method().next method()

They are called differently from yours, namely on a value: first the value, then a dot, then the name. If a method returns a String again, you call the next one right on it, read from left to right.

text: the String on which the method is called, usually a variable like raw or name. It never changes itself: raw.trim(); alone on a line leaves raw unchanged. You store the result in a variable: String clean = raw.trim();
The dot is the dot operator: It calls the method on exactly this value. When you type the dot in the IDE, it suggests all the methods a String has.
method: the name of the method, such as trim, length, or toUpperCase, spelled exactly like this, including uppercase and lowercase letters. The parentheses always belong to it, even if they stay empty: the compiler reports raw.length without parentheses as an error.
Arguments: the values the method needs to work, separated by commas: charAt(0), replace("felix", "franz"). If it needs none, the parentheses stay empty: trim().
next method: It runs on the return value of the method before it. This is called method chaining: In raw.trim().toUpperCase(), toUpperCase() runs on the String without spaces at the edges. If the method before it returns a number like length(), there are no String methods on it: the compiler reports raw.length().trim() as an error.

TextTool.java

public class TextTool {

    public static void main(String[] args) {
        String raw = "  Zombiefelix  ";

        System.out.println(raw.length());
        System.out.println(raw.trim());
        System.out.println(raw.trim().length());
        System.out.println(raw.trim().toUpperCase());
        System.out.println(raw.trim().charAt(0));
        System.out.println(raw.trim().replace("felix", "franz"));
    }

}
CONSOLE

LINE BY LINE

raw.length()counts the characters: 11 letters and the four spaces at the edges, 15 in total.
raw.trim()returns the same text without the spaces at the beginning and end. Nothing changes in raw itself.
raw.trim().toUpperCase()a method chain: toUpperCase() runs right away on the String that trim() returns.
raw.trim().charAt(0)the character at position 0, so the first one: Z.
replace("felix", "franz")replaces every occurrence of “felix” with “franz”.

These six are enough for the start:

  • length(): how many characters? (Spaces count, too.)
  • trim(): cuts off spaces at the beginning and end.
  • toLowerCase() / toUpperCase(): all lowercase, all uppercase.
  • charAt(i): the character at position i. Counting starts at 0.
  • replace(old, replacement): replaces every occurrence.
  • equals(other): compare contents (Chapter 6).

You first, then Java

The spot that catches most people: Below, input.trim(); stands alone on a line, without an assignment. What is in input afterwards? The box asks you for the output before it shows it.

Immutable.java

public class Immutable {

    public static void main(String[] args) {
        String input = "  YES  ";

        input.trim();
        System.out.println("[" + input + "]");

        String clean = input.trim();
        System.out.println("[" + clean + "]");
    }

}
CONSOLE: the square brackets show where the text ends

Remember this

  • A String never changes. trim() does not cut anything off, it returns a new String.
  • If you do not assign this return value to a variable, you calculated for nothing. Just like with your own methods: The return value has to go somewhere.

5.2 User input with Scanner

So far, all values were in the code. A program that asks something must also be able to read the answer. The Scanner takes care of that: It reads what someone types on the keyboard.

STRUCTURE · CLICK A PART

import java.util.Scanner;

Scanner keyboard = new Scanner(System.in);
String text = keyboard.nextLine();

The import goes at the very top, above the class, the other two lines in main. Three lines, and only the third one you have to understand today.

The import statement tells the compiler the package in which the class Scanner lives: java.util. If it is missing, at Scanner the compiler reports the error cannot find symbol. The IDE adds the line for you on request.
Scanner keyboard declares a variable of type Scanner. The name is freely chosen, such as keyboard or sc, but must appear exactly the same again in front of .nextLine(). One Scanner is enough for all input of the program.
new Scanner(System.in) creates a Scanner object and connects it to System.in, the standard input, that is, the keyboard. System.in is the counterpart to System.out. What new does exactly is covered in Chapter 9.
String text declares the variable in which the input is stored. Its type is String, because nextLine() always returns text, even if someone types 17. To calculate with it, you first have to convert it to a number; parsing comes in 5.3.
nextLine() reads the whole typed line up to the Enter key and returns it as a String. Until then, the program waits at this point. Spaces at the edges are kept, which is why .trim() often follows right away.

Greeting.java

import java.util.Scanner;

public class Greeting {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);

        System.out.println("What is your name?");
        String name = keyboard.nextLine();

        System.out.println("Hello " + name.trim() + ".");
    }

}
CONSOLE: typed was “  Mia  ”, with spaces

LINE BY LINE

import java.util.Scanner;tells the compiler where to find the class Scanner. Without this line, it reports cannot find symbol.
new Scanner(System.in)creates the Scanner and connects it to the keyboard (System.in is the standard input, the counterpart to System.out). What new does: Chapter 9. Until then, just write it down, like the main line.
keyboard.nextLine()the interesting part: a method that returns the typed line as a String. You store this return value in a variable, here in name.
name.trim()removes the spaces at the edges of the input: Whoever types “  Mia  ” still gets to read “Hello Mia.”

Remember this

What comes from the keyboard is raw: spaces at the edges, any mix of uppercase and lowercase. With the String methods, you prepare everything that comes from outside before you keep working with it.

Level-up: The trap that catches everyone onceoptional

There is nextInt() for numbers. If you mix it with nextLine(), things get strange: nextInt() reads the number, but the line break from the Enter key stays unread in the input buffer. The next nextLine() reads this empty line and is finished immediately, without waiting.

The fix: a single keyboard.nextLine(); directly after the nextInt(). The return value is deliberately not used here:

Counter.java

import java.util.Scanner;

public class Counter {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);

        System.out.println("How many zombies?");
        int count = keyboard.nextInt();
        keyboard.nextLine();

        System.out.println("What is the first one called?");
        String name = keyboard.nextLine();

        System.out.println(count + " zombies, the first one is called " + name.trim() + ".");
    }

}
CONSOLE: typed was 3, then Zombiefelix

Try leaving out keyboard.nextLine(); in your IDE: The program asks for the name and is finished in the same moment.

Two lines to memorize, one to understand. That is how it is with libraries: You use them long before you see through them. That is the only way anyone ever gets finished.

5.3 Casting and parsing

With nextLine(), you always get text. Even if someone types 17, the variable holds a String. You cannot calculate with it: raw + 1 just appends a 1 to the text. Two ways turn a value into another type, and they only look alike at first glance.

STRUCTURE · CLICK A PART

(target type) number                 Casting: number to number
Wrapper.parsetype(Text)      Parsing: text to number

The four parse methods are all built the same way: wrapper class, dot, parse plus type, such as Integer.parseInt(text).

The parentheses around the type are the cast operator. It stands directly in front of the value and converts it to the type in the parentheses. It is needed when something can get lost, for example from double to int; from int to double it works without a cast.
Target type: the type the value should get, such as int, long, or double. From double to int, the decimal places are dropped, truncated, not rounded: (int) 7.9 gives 7.
Number: the value that is converted, a number or a variable like number. The cast applies only to the value directly after it: (int) 7.9 * 2 gives 14, (int) (7.9 * 2) gives 15.
Wrapper class: the class for the target type, always with a capital first letter: Integer for int, Double for double, Long for long, Boolean for boolean.
Method name: parse, followed by the target type with a capital first letter. int becomes parseInt, double becomes parseDouble. So it is Integer.parseInt, not parseInteger.
Text: the String from which the number is read, such as the input from nextLine(). It may contain only the number, decimal numbers with a decimal point: "4.99". With Integer.parseInt("abc") or Integer.parseInt(" 17"), the program aborts with a NumberFormatException.

Both in one program: parsed at the top, cast at the bottom. The typed input is 17:

Input.java

import java.util.Scanner;

public class Input {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);

        System.out.println("How old are you?");
        String raw = keyboard.nextLine();
        int age = Integer.parseInt(raw);
        System.out.println("Next year: " + (age + 1));

        double number = 7.9;
        System.out.println("Cast: " + (int) number);
    }

}
CONSOLE

LINE BY LINE

String raw = keyboard.nextLine();reads the typed line. 17, too, arrives here as text.
Integer.parseInt(raw)parses: The digits in the text are read as a number. Afterwards, age holds the int 17.
(age + 1)calculates 17 + 1 = 18. The parentheses make sure the calculation happens first and the result is appended to the text afterwards.
(int) numbercasts: The double 7.9 becomes an int, the decimal places are dropped. The result is 7, truncated, not rounded.

Remember this

(int) "42" does not compile. A cast only converts between number types, it cannot turn a text into a number. Parsing exists for that.

Exercise 5.3.1: Casting or parsing?

int b = (int) "7";

incompatible types: String cannot be converted to int. Correct: Integer.parseInt("7").

int d = Integer.parseInt("four");

NumberFormatException, a runtime error. You can catch it: Chapter 11.

int e = (int) 'A';

A char is a number internally. That is why you may cast, and why 'A' + 1 gives 66.

nextInt() takes the parsing off your hands: reading and converting in one step. With nextLine() plus parseInt, however, you keep control. And what if it says twelve there? Chapter 11.

That's enough for now

  • Ready-made methods are called on a value: value, dot, name, such as raw.trim().
  • For the start: length(), trim(), toUpperCase() / toLowerCase(), charAt(i) (from 0), replace(old, replacement).
  • A String never changes. The methods return a new one: Assign the return value to a variable, otherwise it is lost.
  • Scanner: import it, create it with new Scanner(System.in), read with nextLine().
  • What comes from outside is raw: first prepare it with trim() and the like, then keep using it.
  • Casting converts number to number, parsing converts text to number: Integer.parseInt(raw).

Checkpoint

2 questions. Both are traps that almost everyone falls into once.

5. String input = " YES ";, then the line input.trim(); stands alone. What is in input now?

The return value has to go somewhere, as with your own methods. The correct version would be input = input.trim();. Otherwise it is lost.

6. A program reads from the keyboard with Scanner. The line import java.util.Scanner; is missing. What happens?

The import tells the compiler where to find the class Scanner. If it is missing, the compiler does not know the name Scanner, just like with system instead of System. It is also in the Panic glossary.
