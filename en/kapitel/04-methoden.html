Methods

Writing the same code three times is not diligent, it is expensive. Methods are the answer.

approx. 45 min

THE PROBLEM

Three guests are supposed to be greeted. The code for it was copied. Do you notice anything in the output?

Greeting.java

System.out.println("Hello Aylin!");
System.out.println("Nice to have you here, Aylin.");
System.out.println("Hello Mia!");
System.out.println("Nice to have you here, Mia.");
System.out.println("Hello Ben!");
System.out.println("Nice to have you here, Mia.");
CONSOLE

Ben is greeted as Mia: a name got left behind while copying. And you would have to make every change to the greeting three times.

Greeting.java

public class Greeting {

    static void greet(String name) {
        System.out.println("Hello " + name + "!");
        System.out.println("Nice to have you here, " + name + ".");
    }

    public static void main(String[] args) {
        greet("Aylin");
        greet("Mia");
        greet("Ben");
    }

}
CONSOLE

The greeting is written once and called three times, each time with a different name. This chapter shows how to write methods like that.

4.1 Method declaration and signature

The solution: A method is a piece of code with a name. Written once, called as often as you like, each time with different values. (Other languages say function.) It works like a small machine: parameters go in, a return value comes out.

STRUCTURE · CLICK A PART

static return type name(type parameter) {
    statements
    return value;
}

The first line is called the signature: it shows what the method needs and what it returns. If nothing comes back, void stands there, and the return with a value is dropped. Multiple parameters are separated by a comma; without parameters, the parentheses stay empty.

static goes in front of every method you write for now, because main is itself static and can only call other static methods directly. If it is missing, the compiler reports non-static method … cannot be referenced from a static context at the call. What exactly is behind it is explained in the Level-up further down.
Return type: the type of the value the method gives back with return, such as int, double, boolean, or String. For static double twice(…), the result of every call is a double.
Name: freely chosen, starts with a lowercase letter and says what the method does, preferably with a verb: twice, sayHello, calculateSum. The method is called by this name.
Parameter: type and name of a variable that only gets its value at the call, such as double number. Inside the method you use it like any other variable. Each parameter needs its own type: (int a, int b), not (int a, b).
The method body stands between the curly braces: the statements that are executed from top to bottom at every call. There is no semicolon after the signature, just the { directly.
return gives the value back to the place of the call and ends the method immediately. Statements directly after it are never executed.
Value: the result that is returned: a number, a variable, or a calculation like number * 2. Its type must match the return type.

Reading a signature

static double twice(double number) {
    return number * 2;
}

staticrequired in front of every method for now. What it means is explained in the Level-up further down.
doublethe return type: The method returns a value of this type, here a decimal number.

Parameters and return value are optional. That gives exactly four kinds, all here in one program:

Four kinds in one program

Click a method or its call: both light up together. Then “Run”.

Cinema.java

public class Cinema {

    static void greet() {
        System.out.println("Welcome to the cinema!");
    }

    static void showMovie(String title) {
        System.out.println("Now showing: " + title);
    }

    static int freeSeats() {
        return 42;
    }

    static double price(int tickets) {
        return tickets * 8.5;
    }

    public static void main(String[] args) {
        greet();
        showMovie("Zombie Academy");
        int free = freeSeats();
        System.out.println("Free seats: " + free);
        double sum = price(3);
        System.out.println("3 tickets: " + sum + " euros");
    }

}
CONSOLE

Parameters and return value are each optional, which gives four kinds. The methods stand next to main, and they are called in main.

Kind 1: nothing in, nothing out. Return type void, empty parentheses. It is called as a statement of its own: greet();
Kind 2: something in, nothing out. The parameter String title gets the value from the parentheses at the call: showMovie("Zombie Academy"); Return type void, so nothing comes back.
Kind 3: nothing in, something out. Empty parentheses, return type int. At the call, you store the return value in a variable of the same type: int free = freeSeats();
Kind 4: something in, something out. Parameter int tickets, return type double. price(3) calculates 3 * 8.5 and returns 25.5, and the value ends up in sum.
return returns the value after it and ends the method. The value must match the return type. Methods with void do not need return.
main calls the methods one after the other. The methods themselves stand next to it in the same class, not inside main.

You already know two methods: Java calls main automatically, and you have been calling System.out.println(…) yourself since Chapter 2. The only new thing: You build your own.

4.2 Method calls and return values

A method only runs when someone calls it: with its name and the values in the parentheses. What it returns with return, you catch in a variable or keep calculating with directly.

STRUCTURE · CLICK A PART

name(arguments);
type variable = name(arguments);

You write your own methods in the same class as main: next to it, not inside it. The first line calls a method and lets it work, the second also catches its return value.

Name of the method: spelled exactly as in the signature, including uppercase and lowercase. The parentheses belong to every call, even without arguments: rollDie().
Arguments: the values for the parameters, separated by commas, such as "Aylin" or 2, 3. Number, order, and types must match the parameter list. The type is not written in front at the call: sayHello("Ben"), not sayHello(String "Ben").
Type of the variable: must match the return type of the method. If rollDie() returns an int, you write int pips = rollDie();. A void method returns no value, so its call cannot stand to the right of the =.
Variable: a freely chosen name under which the return value is stored. After that you work with it like any other variable, such as System.out.println(pips);.
The equals sign assigns: first the method is executed, then its return value is stored in the variable on the left.

ZombieApocalypse.java

public class ZombieApocalypse {

    public static void main(String[] args) {
        sayHello("Aylin");        // call 1
        sayHello("Ben");          // call 2, same code, different value!
        sayHello("Ben");          // works twice, too. Ben is happy.
    }

    static void sayHello(String name) {
        System.out.println("Hi, " + name + "!");
    }

}
CONSOLE

LINE BY LINE

sayHello("Aylin");the call: Java jumps into the method, and the parameter name gets the value "Aylin". Then it continues in main.
sayHello("Ben");the same code with a different value. One call instead of a copy, and twice is fine, too.
void sayHello(String name)stands next to main, not in it. void: The method outputs something, nothing comes back.

If the greeting changes, you change it in exactly one place.

The rule behind it is called DRY, “Don't Repeat Yourself”. It does not mean “type little”, but: Every piece of knowledge lives in exactly one place. If the profile card is in the code five times, you will eventually forget one place when changing it. Not maybe: for sure.

Return values can be used in further calculations, right inside println. What comes out? Write down your prediction before you run it.

static int square(int x) {
    return x * x;
}

System.out.println(square(3) + 1);      // ???
System.out.println(square(2 + 1));      // ??? (watch the parentheses!)
CONSOLE

10 and 9. With square(3) + 1, the squaring comes first (9), then the addition. With square(2 + 1), the parentheses come first (3), and then it is squared.

Remember this

  • void: Nothing comes back. The method only does something (e.g. output). Nothing can be stored, there is no result.
  • A type instead of void (e.g. int): The method must deliver a matching value with return. You catch it: int pips = rollDie();
  • Parameters are variables that get their value at the call. The values you pass are called arguments. The compiler checks their types as strictly as with any assignment.
  • return ends the method immediately. The compiler rejects code directly after it (unreachable statement).

4.3 Scope of variables

A variable is valid in the block { … } in which it was declared: from its line to the closing brace. That is its scope. It explains why parameters and return are needed.

Zone.java

public class Zone {

    static int doubleIt(int value) {
        int result = value * 2;
        return result;
    }

    public static void main(String[] args) {
        int supply = 5;
        System.out.println(doubleIt(supply));
    }

}
CONSOLE

Click a variable in the code. The lines where it is valid stay highlighted: its scope.

value is a parameter and is valid in doubleIt, up to its closing brace. main does not know it. At the call it gets a copy of the argument, here the 5 from supply.
result is valid from its declaration to the end of doubleIt. With return, only the value 10 leaves the method, the variable itself does not exist outside.
supply is valid in main, from its line to the closing brace of main. doubleIt does not know the name, but calculates with the 5: It was passed as a copy.

Remember this

Between methods there are only two ways for values: in through the parameters, out through return. All other variables are valid only in their own method.

4.4 Overloading methods

Two methods may have the same name if the compiler can tell them apart by the parameter list. This is called overloading. You have been using it since Chapter 2: System.out.println accepts text, integers, decimal numbers, boolean. No magic: println exists ten times, once for each kind.

STRUCTURE · CLICK A PART

static type name(parameter list A) { … }
static type name(parameter list B) { … }

The parameter lists must differ in number, types, or order. Which version runs is decided by the compiler at the call, based on the number and type of the arguments.

Return type: may be the same or different in both versions. But it alone does not tell them apart: The compiler rejects two methods with the same name and the same parameter list, even if their return types differ.
Same name in both lines, spelled exactly the same. That is overloading: one name for the same task with different parameters, such as add for two or for three numbers.
Parameter list A: the parameters of the first version, such as int a, int b. The call add(2, 3) runs this version.
Parameter list B: must differ from A, such as int a, int b, int c or double a, double b. Different parameter names alone are not enough: int x, int y counts as the same list as int a, int b.
The method body { … }: Each version is a complete method with its own body. The dots are only placeholders for the statements here.

Adder.java (excerpt)

static int add(int a, int b) {
    return a + b;
}

static int add(int a, int b, int c) {
    return a + b + c;
}

static double add(double a, double b) {
    return a + b;
}

LINE BY LINE

add(int a, int b)two integers. Runs for add(2, 3).
add(int a, int b, int c)three integers. Runs for add(2, 3, 4).
add(double a, double b)two decimal numbers. Runs for add(2.5, 3.5).

Remember this

  • What counts is the parameter list: number, types, order.
  • The return type does not count. If two methods differ only in that, it is not overloading but a compile error.

Why? The compiler picks the version at the call site, and only the arguments are there.

Exercise 4.4.1: Which one is called?

Predict the console. The last line is the interesting one: There is no add(int, double) at all.

Adder.java

public class Adder {

    static int add(int a, int b) {
        return a + b;
    }

    static int add(int a, int b, int c) {
        return a + b + c;
    }

    static double add(double a, double b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(add(2, 3));
        System.out.println(add(2, 3, 4));
        System.out.println(add(2.5, 3.5));
        System.out.println(add(2, 3.5));
    }

}
CONSOLE

At the last call add(2, 3.5), the third version runs as well: Java turns the 2 into a 2.0.

That's enough for now

  • Method = code with a name: write it once, call it as often as you like. House rule (DRY): If you want to copy code, write a method.
  • Reading a signature: return type · name · parameters.
  • void = nothing comes back. Otherwise return delivers the value and ends the method immediately.
  • Return values can be caught and used in further calculations.
  • A variable is valid only in its block. Values get in only via parameters and out only via return.
  • Overloading: same name, different parameter list. The return type does not count.

Checkpoint

4 questions about methods.

1. What does static int countZombies() tell you about the method?

Return type int (before the name), empty parentheses = no parameters.

2. A method is declared as void. What follows from that?

void = no return value. The method does something but returns nothing. It may still have parameters.

3. Given: static void sayHello(String name). What happens with sayHello(42);?

Arguments must match the parameter types. Wrong type → the program does not even compile.

4. What does return do?

return gives the result back to the caller and ends the method. Printing is the job of System.out.println.
