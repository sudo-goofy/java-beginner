The Panic glossary

Ten error messages that are guaranteed to catch you, verbatim, explained in plain English.

10 messages Reference

On this page

The one rule

An error message is not an insult but a precise statement: which file, which line, which problem. Read first, then swear, then fix.

There are two kinds: compiler errors (the program does not start at all) and runtime errors (it ran and crashed midway). Recognizing the kind already halves your search. The logic error from Chapter 1 never announces itself and is therefore missing here.

All messages are real, from javac and the JVM (OpenJDK 25). If your output differs slightly, that is down to your Java version. The cause stays the same.

Compiler errors: the program does not start

These messages appear before anything runs. A caret (^) points to the spot where the compiler finds the error.

1. ';' expected

CompilerChapter 2

A.java:3: error: ';' expected
        System.out.println("Hello")
                                   ^
1 error

In plain English

“A semicolon is missing.” The classic. The caret sits right after the last character of the affected line. A forgotten bracket, on the other hand, is often reported by the compiler only further down.

Instant check

  • Look at the line it names and the line above it.
  • Does every statement end with ;?

2. package system does not exist

CompilerChapter 2

B.java:4: error: package system does not exist
        system.out.println(name);
              ^
1 error

In plain English

System is written in lowercase. The compiler then reads system.out as “the package system,” and that does not exist. Upper and lower case always matter in Java.

Instant check

  • System capitalized, out and println lowercase.
  • The same goes for these: String capitalized, int lowercase.

3. cannot find symbol

CompilerChapter 3Chapter 4Chapter 6

G.java:7: error: cannot find symbol
        System.out.println(teil);
                           ^
  symbol:   variable teil
  location: class G
1 error

In plain English

The compiler does not know the name at this spot. Either a typo or, more often: the variable exists, but not at this spot. Declared inside a loop or an if block, it is no longer valid after the closing brace. This is called scope (Chapter 4).

Instant check

  • The symbol: line names the unknown word: compare it letter by letter.
  • Is the declaration inside a block { … } that you have already left? Then declare it further up.

4. incompatible types

CompilerChapter 3

C.java:3: error: incompatible types: String cannot be converted to int
        int age = "twenty";
                    ^
1 error

In plain English

The value does not match the variable’s type. The message names both types: X cannot be converted to Y. X is the type of the value, Y the type of the variable.

Instant check

  • What is wrong, the type of the variable or the value?
  • A decimal number in an int? Either use double or truncate deliberately: (int) 4.9 gives 4.

5. class X is public, should be declared in a file named X.java

CompilerChapter 2

D.java:1: error: class Lager is public, should be declared in a file named Lager.java
public class Lager {
       ^
1 error

In plain English

Class name and file name must match exactly, including upper and lower case: class Lager, file Lager.java.

Instant check

  • Let the IDE rename it; it catches the class, the file and every use: VS Code: cursor on the name, F2 · IntelliJ IDEA: cursor on the name, Shift + F6
  • There is exactly one public class per file.

6. variable X might not have been initialized

CompilerChapter 3

J.java:4: error: variable hunger might not have been initialized
        System.out.println(hunger);
                           ^
1 error

In plain English

The variable is declared but does not have a value yet. The compiler won’t let you read it like that, unlike some languages that silently take some value instead.

Instant check

  • Give it a starting value right at the declaration: int hunger = 0;
  • A value that is only set in one if branch does not count: the other branch might run.

7. missing return statement

CompilerChapter 4

I.java:4: error: missing return statement
    }
    ^
1 error

In plain English

The signature has a return type (here int), but one path through the method ends without returning anything. The caret points to the closing brace: that is where the return is missing.

Instant check

  • Does every possible path end with a return? The else branch too?
  • If nothing should come back: return type void.

8. constructor X cannot be applied to given types

CompilerChapter 9

K.java:7: error: constructor Zombie in class Zombie cannot be applied to given types;
        Zombie z = new Zombie();
                   ^
  required: String
  found:    no arguments
  reason: actual and formal argument lists differ in length
1 error

In plain English

The constructor receives different values than it requires. The message is unusually detailed: required is what it needs, found is what arrived.

Instant check

  • Which parameters are in the constructor’s parentheses?
  • Once you write your own constructor, the empty default constructor disappears: new Zombie() then works only if you add it yourself.

Runtime errors: the program ran and crashed

The compiler has compiled the code; the error only occurs when you run it. The bottom at … line names the spot in your code.

9. ArrayIndexOutOfBoundsException

RuntimeChapter 8

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
	at E.main(E.java:4)

In plain English

You are accessing an index that does not exist in the array. Index 5 with length 5: five elements have the indices 0 to 4. The last index is always length - 1.

Instant check

  • Check the loop condition: i < array.length, not i <= array.length.
  • For arrays, length has no parentheses: array.length, not array.length(). Only for String is it a method.

10. NullPointerException

RuntimeChapter 9

Exception in thread "main" java.lang.NullPointerException: Cannot invoke "Zombie.groan()" because "camp[2]" is null
	at Lager.main(Lager.java:6)

In plain English

The variable points to no object (null), so there is nothing whose method you could call. Since Java 14, the message names the variable that is null, here camp[2].

Instant check

  • After new Zombie[3] the array is empty: three elements, all null. Every object needs its own new.
  • Search backwards from the named variable: where did it last get a value?

Bonus: NumberFormatException

RuntimeInput

Exception in thread "main" java.lang.NumberFormatException: For input string: "zwoelf"
	at java.base/java.lang.Integer.parseInt(Integer.java:565)
	at Lager.main(Lager.java:3)

In plain English

A number was supposed to arrive, but text arrived. The at java.base/… lines belong to the Java library. Only the bottom line matters: it points to your code.

Instant check

  • Read from top to bottom: the first at line with your file name is the spot in your code.
  • For input string: shows literally what arrived.

How to read any message, even an unfamiliar one

  1. Determine the kind. error: means compiler error, Exception in thread means: the program was already running.
  2. Find the place. File.java:7 means: file File.java, line 7. For runtime errors, the bottom at … line with your file name is the one that counts.
  3. First message first. One missing semicolon can trigger twenty follow-up errors. Fix only the topmost one, then compile again.
  4. Take the sentence literally. cannot be converted to int means exactly that. The message is right, even if it is terse.

Remember this

Being able to read error messages: the most underrated skill in programming, and the only one that gets better with every error.
