Die eine Regel

Eine Fehlermeldung ist keine Beleidigung, sondern eine genaue Angabe: welche Datei, welche Zeile, welches Problem. Erst lesen, dann fluchen, dann beheben.

Es gibt zwei Sorten: Compiler-Fehler (das Programm startet gar nicht) und Laufzeitfehler (es lief und ist mittendrin abgestürzt). Die Sorte zu erkennen halbiert schon die Suche. Der Logikfehler aus Kapitel 1 meldet sich gar nicht und fehlt deshalb hier.

Alle Meldungen sind echt, aus javac und der JVM (OpenJDK 25). Weicht deine Ausgabe leicht ab, liegt das an deiner Java-Version. Die Ursache bleibt dieselbe.

Compiler-Fehler: Das Programm startet nicht

Diese Meldungen erscheinen, bevor etwas läuft. Ein Dach (^) zeigt auf die Stelle, an der der Compiler den Fehler findet.

1. ';' expected

CompilerKapitel 2

A.java:3: error: ';' expected
        System.out.println("Hello")
                                   ^
1 error

Auf Deutsch heißt das

„Da fehlt ein Semikolon.“ Der Klassiker. Das Dach steht direkt hinter dem letzten Zeichen der betroffenen Zeile. Eine vergessene Klammer dagegen meldet der Compiler oft erst weiter unten.

Sofort-Check

  • Die genannte Zeile ansehen und die Zeile darüber.
  • Endet jede Anweisung mit ;?

2. package system does not exist

CompilerKapitel 2

B.java:4: error: package system does not exist
        system.out.println(name);
              ^
1 error

Auf Deutsch heißt das

System ist kleingeschrieben. Der Compiler liest system.out dann als „das Paket system“, und das gibt es nicht. Groß und klein zählt in Java immer.

Sofort-Check

  • System groß, out und println klein.
  • Genauso: String groß, int klein.

3. cannot find symbol

CompilerKapitel 3Kapitel 4Kapitel 6

G.java:7: error: cannot find symbol
        System.out.println(teil);
                           ^
  symbol:   variable teil
  location: class G
1 error

Auf Deutsch heißt das

Der Compiler kennt den Namen an dieser Stelle nicht. Entweder ein Tippfehler oder, häufiger: Die Variable existiert, aber nicht an dieser Stelle. In einer Schleife oder einem if-Block deklariert, gilt sie hinter der schließenden Klammer nicht mehr. Das heißt Gültigkeitsbereich (Kapitel 4).

Sofort-Check

  • Die Zeile symbol: nennt das unbekannte Wort: Buchstabe für Buchstabe vergleichen.
  • Steht die Deklaration innerhalb eines Blocks { … }, den du schon verlassen hast? Dann weiter oben deklarieren.

4. incompatible types

CompilerKapitel 3

C.java:3: error: incompatible types: String cannot be converted to int
        int age = "twenty";
                    ^
1 error

Auf Deutsch heißt das

Der Wert passt nicht zum Typ der Variablen. Die Meldung nennt beide Typen: X cannot be converted to Y. X ist der Typ des Werts, Y der Typ der Variablen.

Sofort-Check

  • Was ist falsch, der Typ der Variablen oder der Wert?
  • Kommazahl in einem int? Entweder double nehmen oder bewusst abschneiden: (int) 4.9 ergibt 4.

5. class X is public, should be declared in a file named X.java

CompilerKapitel 2

D.java:1: error: class Lager is public, should be declared in a file named Lager.java
public class Lager {
       ^
1 error

Auf Deutsch heißt das

Klassenname und Dateiname müssen exakt übereinstimmen, auch in Groß- und Kleinschreibung: Klasse Lager, Datei Lager.java.

Sofort-Check

  • Lass die IDE umbenennen, sie erwischt Klasse, Datei und jede Benutzung: VS Code: Cursor auf den Namen, F2 · IntelliJ IDEA: Cursor auf den Namen, Umschalt + F6
  • Pro Datei gibt es genau eine public class.

6. variable X might not have been initialized

CompilerKapitel 3

J.java:4: error: variable hunger might not have been initialized
        System.out.println(hunger);
                           ^
1 error

Auf Deutsch heißt das

Die Variable ist deklariert, hat aber noch keinen Wert. Lesen lässt der Compiler sie so nicht, anders als manche Sprachen, die dann stillschweigend irgendeinen Wert nehmen.

Sofort-Check

  • Startwert gleich bei der Deklaration: int hunger = 0;
  • Ein Wert, der nur in einem if-Zweig gesetzt wird, zählt nicht: Es könnte ja der andere Zweig laufen.

7. missing return statement

CompilerKapitel 4

I.java:4: error: missing return statement
    }
    ^
1 error

Auf Deutsch heißt das

In der Signatur steht ein Rückgabetyp (hier int), aber ein Weg durch die Methode endet ohne Rückgabe. Das Dach zeigt auf die schließende Klammer: Dort fehlt das return.

Sofort-Check

  • Endet jeder mögliche Weg mit einem return? Auch der else-Zweig?
  • Soll nichts zurückkommen: Rückgabetyp void.

8. constructor X cannot be applied to given types

CompilerKapitel 9

K.java:7: error: constructor Zombie in class Zombie cannot be applied to given types;
        Zombie z = new Zombie();
                   ^
  required: String
  found:    no arguments
  reason: actual and formal argument lists differ in length
1 error

Auf Deutsch heißt das

Der Konstruktor bekommt andere Werte, als er verlangt. Die Meldung ist ungewöhnlich ausführlich: required ist, was er braucht, found, was kam.

Sofort-Check

  • Welche Parameter stehen in den Klammern des Konstruktors?
  • Mit einem eigenen Konstruktor verschwindet der leere Standardkonstruktor: new Zombie() geht dann nur noch, wenn du ihn selbst dazuschreibst.

Laufzeitfehler: Das Programm lief und stürzte ab

Der Compiler hat übersetzt, der Fehler tritt erst beim Ausführen auf. Die unterste Zeile at … nennt die Stelle in deinem Code.

9. ArrayIndexOutOfBoundsException

LaufzeitKapitel 8

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
	at E.main(E.java:4)

Auf Deutsch heißt das

Du greifst auf einen Index zu, den es im Array nicht gibt. Index 5 bei length 5: Fünf Elemente haben die Indizes 0 bis 4. Der letzte Index ist immer length - 1.

Sofort-Check

  • Schleifenbedingung prüfen: i < array.length, nicht i <= array.length.
  • length steht bei Arrays ohne Klammern: array.length, nicht array.length(). Nur beim String ist es eine Methode.

10. NullPointerException

LaufzeitKapitel 9

Exception in thread "main" java.lang.NullPointerException: Cannot invoke "Zombie.groan()" because "camp[2]" is null
	at Lager.main(Lager.java:6)

Auf Deutsch heißt das

Die Variable verweist auf kein Objekt (null), also gibt es auch nichts, dessen Methode man aufrufen könnte. Seit Java 14 nennt die Meldung die Variable, die null ist, hier camp[2].

Sofort-Check

  • Nach new Zombie[3] ist das Array leer: drei Elemente, alle null. Jedes Objekt braucht sein eigenes new.
  • Von der genannten Variablen rückwärts suchen: Wo hat sie zuletzt einen Wert bekommen?

Zugabe: NumberFormatException

LaufzeitEingaben

Exception in thread "main" java.lang.NumberFormatException: For input string: "zwoelf"
	at java.base/java.lang.Integer.parseInt(Integer.java:565)
	at Lager.main(Lager.java:3)

Auf Deutsch heißt das

Eine Zahl sollte kommen, gekommen ist Text. Die at java.base/…-Zeilen gehören zur Java-Bibliothek. Wichtig ist nur die unterste Zeile: Sie zeigt auf deinen Code.

Sofort-Check

  • Von oben nach unten lesen: Die erste at-Zeile mit deinem Dateinamen ist die Stelle in deinem Code.
  • For input string: zeigt wörtlich, was ankam.

So liest du jede Meldung, auch eine unbekannte

  1. Sorte bestimmen. error: heißt Compiler-Fehler, Exception in thread heißt: Das Programm lief schon.
  2. Ort suchen. File.java:7 heißt: Datei File.java, Zeile 7. Bei Laufzeitfehlern zählt die unterste at …-Zeile mit deinem Dateinamen.
  3. Erste Meldung zuerst. Ein fehlendes Semikolon kann zwanzig Folgefehler auslösen. Nur den obersten beheben, neu übersetzen.
  4. Den Satz wörtlich nehmen. cannot be converted to int heißt genau das. Die Meldung stimmt, auch wenn sie knapp ist.

Merk dir das

Fehlermeldungen lesen können: die unterschätzteste Fähigkeit beim Programmieren, und die einzige, die mit jedem Fehler besser wird.
