Vererbung & abstrakte Klassen

Drei Klassen, die sich zu achtzig Prozent gleichen: Das ist kein Zufall, sondern ein Hinweis.

ca. 40 min

DAS PROBLEM

Circle und Rectangle lassen sich verschieben. Der Code dafür ist kopiert. Wo landen beide?

Moving.java

class Circle {
    int x = 10, y = 10;
    void move(int dx, int dy) { x = x + dx; y = y + dy; }
}

class Rectangle {
    int x = 10, y = 10;
    void move(int dx, int dy) { x = x + dx; y = y + dx; }
}

public class Moving {

    public static void main(String[] args) {
        Circle k = new Circle();
        Rectangle r = new Rectangle();
        k.move(5, 0);
        r.move(5, 0);
        System.out.println("Circle at (" + k.x + ", " + k.y + ")");
        System.out.println("Rectangle at (" + r.x + ", " + r.y + ")");
    }

}
KONSOLE

Das Rectangle ist schräg verrutscht: In der kopierten Methode steht dx statt dy. Derselbe Code steht zweimal, also kann er auch an zwei Stellen falsch sein.

Moving.java

class Shape {
    int x = 10, y = 10;
    void move(int dx, int dy) { x = x + dx; y = y + dy; }
}

class Circle extends Shape { }

class Rectangle extends Shape { }

public class Moving {

    public static void main(String[] args) {
        Circle k = new Circle();
        Rectangle r = new Rectangle();
        k.move(5, 0);
        r.move(5, 0);
        System.out.println("Circle at (" + k.x + ", " + k.y + ")");
        System.out.println("Rectangle at (" + r.x + ", " + r.y + ")");
    }

}
KONSOLE

Was beide gemeinsam haben, steht einmal in der Oberklasse Shape. Circle und Rectangle erben es. Wie Vererbung funktioniert, zeigt dieses Kapitel.

In diesem Kapitel

Danach kannst du

10.1 Vererbung mit extends

Ein Zeichenprogramm hat die Klassen Circle und Rectangle. Beide haben eine Position (x, y), beide kann man verschieben und zeichnen. Statt alles zweimal zu schreiben, kommt Gemeinsames in eine Oberklasse (auch „Mutterklasse“), und die Unterklassen (auch „Kindklassen“) erben es.

AUFBAU · KLICK AUF EINEN TEIL

public class Unterklasse extends Oberklasse {
    nur das, was die Unterklasse zusätzlich hat
}

extends heißt „erbt von“. Was die Oberklasse hat, hat die Unterklasse auch, ohne es selbst zu deklarieren.

Unterklasse: die neue, speziellere Klasse, etwa Circle. Ein Objekt der Unterklasse ist zugleich ein Objekt der Oberklasse: Jeder Circle ist eine Shape.
extends verbindet die Unterklasse mit ihrer Oberklasse. Dahinter steht genau ein Klassenname, denn mehrere Oberklassen auf einmal erlaubt Java nicht.
Oberklasse: die allgemeinere Klasse mit dem, was alle Unterklassen gemeinsam haben, etwa Shape mit x, y und move(). Änderst du dort etwas, gilt die Änderung für alle Unterklassen.
Klassenrumpf der Unterklasse: nur, was dazukommt: eigene Attribute wie private int radius;, ein eigener Konstruktor und eigene Fassungen von Methoden. Geerbte Attribute wie x deklarierst du hier nicht noch einmal.

Shape.java + Circle.java

public abstract class Shape {              // die Oberklasse
    protected int x;                        // protected: auch in Unterklassen sichtbar
    protected int y;

    public void move(int dx, int dy) {
        x = x + dx;
        y = y + dy;
    }

    public abstract void draw();         // Jede Unterklasse muss draw() überschreiben.
}

public class Circle extends Shape {          // extends = "erbt von"
    private int radius;

    public Circle(int x, int y, int radius) {
        this.x = x;                          // x und y? Geerbt! Nie selbst deklariert.
        this.y = y;
        this.radius = radius;
    }

    @Override
    public void draw() {
        System.out.println(" Circle at (" + x + "," + y + "), r=" + radius);
    }
}

ZEILE FÜR ZEILE

protected int x;Die Position steht nur einmal, in der Oberklasse. protected macht sie auch für die Unterklassen sichtbar.
public void move(…)Auch das Verschieben steht nur in Shape. Jeder Circle kann es trotzdem, denn er erbt es.
public abstract void draw();Jede Shape kann sich zeichnen, aber wie, legt erst die Unterklasse fest.
class Circle extends ShapeCircle erbt alles von Shape und schreibt nur noch, was ihn besonders macht.
private int radius;das Eigene: Einen Radius hat nur der Circle.
this.x = x;x und y sind geerbt, nie in Circle deklariert. Circle setzt sie hier von Hand, weil protected das erlaubt. Hat die Oberklasse einen eigenen Konstruktor, übernimmt das super(…), so wie in allen weiteren Beispielen.
@OverrideHier füllt Circle sein eigenes draw() aus.

Merk dir das

  • Generalisierung: nach oben zusammenfassen. Spezialisierung: nach unten verfeinern.
  • Der Vererbungspfeil im UML zeigt zur Oberklasse: Circle → Shape.

10.2 super, protected und abstrakte Klassen

Die Oberklasse vererbt nicht nur Attribute. Ihr Konstruktor richtet ihren Teil des Objekts ein (super), sie kann Attribute für ihre Unterklassen freigeben (protected), und sie darf ein reines Konzept sein, das erst die Unterklassen ausfüllen (abstract).

AUFBAU · KLICK AUF EINEN TEIL

public abstract class Oberklasse {
    public abstract Typ methode();
}

public class Unterklasse extends Oberklasse {
    public Unterklasse(Parameter) {
        super(Argumente);
    }

    @Override
    public Typ methode() {
        wie die Unterklasse es macht
    }
}

super(…) steht in der ersten Zeile des Konstruktors der Unterklasse und ruft den Konstruktor der Oberklasse auf. Eine abstrakte Methode hat keinen Rumpf, nur ein Semikolon.

abstract vor class: Von dieser Klasse gibt es keine Objekte, bei new Shape() meldet der Compiler einen Fehler. abstract vor einer Methode: Sie besteht nur aus dem Methodenkopf, und jede nicht abstrakte Unterklasse muss sie überschreiben. Eine Klasse mit einer abstrakten Methode muss selbst abstract sein.
Oberklasse: die allgemeine Klasse, etwa Zombie. Sie legt fest, was alle Unterklassen gemeinsam haben, hier auch, dass jede die Methode besitzt. In der Unterklasse steht ihr Name hinter extends.
Rückgabetyp und Methodenname: In der Unterklasse stehen sie genau wie bei der abstrakten Methode, ebenso die Parameter, etwa public void groan(). Nur dann überschreibt die Unterklasse die Methode der Oberklasse.
Unterklasse: die spezielle Klasse, etwa Walker. Ihr Konstruktor heißt genau wie sie und hat keinen Rückgabetyp: public Walker(…).
Parameter: alle Werte, die ein neues Objekt der Unterklasse braucht, auch die für den geerbten Teil: public Walker(String name, int age).
super(…) gibt die Argumente an den Konstruktor der Oberklasse weiter, der damit die geerbten Attribute setzt: super(name, age);. Anzahl und Typen müssen zu diesem Konstruktor passen. Hat die Oberklasse nur Konstruktoren mit Parametern und fehlt super(…), meldet der Compiler einen Fehler.
@Override steht direkt über einer Methode, die eine Methode der Oberklasse überschreibt. Der Compiler prüft, ob es dort eine passende gibt: Bei einem Tippfehler wie groans() meldet er einen Fehler, statt still eine neue Methode anzulegen.
Methodenrumpf: wie genau diese Unterklasse die Methode ausführt, etwa System.out.println(name + " groans: Grrr!");. Jede Unterklasse schreibt hier ihre eigene Fassung.
  • extends: „erbt von“. Die Unterklasse hat alles von der Oberklasse, plus Eigenes. Nur eine Oberklasse pro Klasse.
  • protected: Stufe zwischen private und public. Die eigene Klasse und ihre Unterklassen dürfen zugreifen. (Auch Klassen im selben Paket dürfen zugreifen, ohne eigene Pakete also dein ganzes Projekt.)
  • super: Mit super(…) ruft der Konstruktor der Unterklasse den Konstruktor der Oberklasse auf. Der richtet den geerbten Teil des Objekts ein. Mit super.method() rufst du die Fassung der Oberklasse auf.
  • abstract: Bei Klassen: nur Konzept, nicht instanziierbar (new Shape() übersetzt nicht). Bei Methoden: kein Rumpf, nur Semikolon, jede Unterklasse muss sie implementieren.
  • @Override: markiert eine Methode, die eine Methode der Oberklasse absichtlich überschreibt. Der Compiler prüft, ob es dort eine passende Methode gibt.

Warum abstract? Was wäre new Shape(): rund, eckig, beides? Eine „Shape an sich“ gibt es nicht, nur konkrete Figuren. abstract sagt: Diese Klasse ist nur ein Konzept. Teste es unten.

Erst du, dann Java

Was erscheint bei new Walker("Mia", 2); zuerst: die Meldung der Oberklasse (Zombie) oder die der Unterklasse (Walker)? Beide Konstruktoren melden sich per println. Sag die Reihenfolge voraus:

Baureihenfolge.java (Ausschnitt)

public Zombie(String name, int age) {
    this.name = name;
    this.age = age;
    System.out.println("Zombie part built");
}

public Walker(String name, int age) {
    super(name, age);                       //  die entscheidende Zeile
    System.out.println("Walker part built");
}

// in der main:
new Walker("Mia", 2);
KONSOLE
Auflösung: erst ausführen, dann aufklappen!

Zuerst die Oberklasse (Zombie part built), dann die Unterklasse: super(…) steht in der ersten Zeile und ruft sofort den Konstruktor der Oberklasse auf. Der geerbte Teil des Objekts wird zuerst eingerichtet.

10.3 Polymorphie und Überschreiben

Gleicher Aufruf, passende Antwort pro Objekt. Deshalb laufen Schleifen über den Obertyp auch mit Klassen, die es heute noch nicht gibt.

AUFBAU · KLICK AUF EINEN TEIL

Oberklasse[] name = { new Unterklasse(…), new andere Unterklasse(…) };

for (Oberklasse element : name) {
    element.methode();
}

Das Array hat den Typ der Oberklasse, seine Elemente sind Objekte der Unterklassen. Jedes bringt seine eigene Fassung der Methode mit.

Oberklasse als Typ: Vorn hat das Array den Typ Shape[], in der Schleife die Variable den Typ Shape. Eine Variable vom Typ der Oberklasse kann eine Referenz auf ein Objekt jeder Unterklasse speichern.
Name des Arrays: frei wählbar, etwa picture. Hinter dem Doppelpunkt der Schleife steht derselbe Name: Die Schleife geht genau dieses Array durch.
Objekte der Unterklassen: Jedes new erzeugt ein Objekt einer konkreten Unterklasse, etwa new Circle(60, 45, 30) oder new Rectangle(150, 25, 90, 55). new Shape(…) geht nicht, denn von einer abstrakten Klasse gibt es keine Objekte.
Schleifenvariable: In jeder Runde enthält sie die Referenz auf das nächste Element, etwa f. Ihr Typ bleibt die Oberklasse, auch wenn gerade ein Circle an der Reihe ist.
Der Doppelpunkt macht daraus eine for-each-Schleife, lies ihn als „in“: für jede Shape f in picture. Die Schleife nimmt nacheinander jedes Element, ganz ohne Index.
Methode: Sie muss in der Oberklasse deklariert sein, sonst meldet der Compiler bei f.draw() einen Fehler, denn er kennt nur den Typ Shape. Welche Fassung läuft, entscheidet sich erst beim Ausführen am tatsächlichen Objekt: beim Circle die von Circle.

Das Finale: Polymorphie live

Ein Array voller Figuren (geht, weil Circle und Rectangle beide „Figuren sind“). Alle bekommen denselben Aufruf draw(), jedes Objekt antwortet auf seine Art. Das is Polymorphie („Vielgestaltigkeit“).

Leinwand.java

Shape[] picture = { new Circle(60, 45, 30),
                 new Rectangle(150, 25, 90, 55),
                 new Circle(290, 50, 20) };

for (Shape f : picture) {
    f.draw();     // gleicher Aufruf, drei verschiedene Ergebnisse!
}

ZEILE FÜR ZEILE

Shape[] picture = { … };ein Array vom Typ der Oberklasse. Hinein darf jedes Objekt, das eine Shape ist: Kreise und Rechtecke.
for (Shape f : picture)geht alle Elemente durch. Für die Schleife ist f einfach eine Shape.
f.draw();derselbe Aufruf für alle. Ein Circle zeichnet sich als Circle, ein Rectangle als Rectangle.

Merk dir das

  • Die Schleife oben weiß nicht, welche Figuren im Array liegen. Muss sie auch nicht.
  • Kommt Triangle extends Shape dazu, läuft sie unverändert: Das Triangle zeichnet sich selbst.
  • Das Prinzip: Programmiere gegen das Allgemeine (Shape), nicht gegen das Spezielle (Circle). So bleibt ein Programm erweiterbar, ohne dass man alten Code anfasst.

In echten Projekten heißt das: „Feature in 2 Stunden“ statt „Feature in 2 Wochen“.

Level-Up: Woher weiß ich, dass mein Code stimmt? (Mini-Ausblick: Tests)optional

Profis klicken ihr Programm nicht hundertmal von Hand durch. Sie schreiben Tests, kleine Programme, die das eigene Programm prüfen. In Java mit JUnit:

FigurTest.java

@Test
void moveAddsCorrectly() {
    Circle k = new Circle(10, 10, 5);
    k.move(5, -3);
    assertEquals(15, k.x);   // erwarte: x ist jetzt 15
    assertEquals(7, k.y);    // erwarte: y ist jetzt 7 (protected: der Test liegt im selben Paket)
}

Grün: Die Logik stimmt. Rot: Du weißt sofort, wo’s klemmt. Zwei Sorten von Tests:

  • Blackbox-Tests: nur Eingabe und Ausgabe anschauen, Innenleben egal.
  • Whitebox-Tests: gezielt alle Code-Wege prüfen.

Mehr dazu im Unterricht.

Das reicht für jetzt

  • Gemeinsames in die Oberklasse. Unterklassen erben mit extends und ergänzen ihr Spezielles.
  • protected: Auch die Unterklassen dürfen zugreifen.
  • super(…): Der Konstruktor der Oberklasse läuft zuerst.
  • abstract: Konzept ohne Exemplare. @Override: absichtlich überschreiben.
  • Polymorphie: gleicher Aufruf, passende Antwort pro Objekt.
  • Deshalb laufen Schleifen über den Obertyp auch mit Klassen, die es heute noch nicht gibt.

Checkpoint

5 Fragen zu Vererbung und Polymorphie.

1. public class Circle extends Shape: was bedeutet das?

extends = „erbt von“. Die Richtung: Die Unterklasse (Circle) steht vorne, die Oberklasse (Shape) hinten.

2. Warum scheitert new Shape()?

abstract verhindert die Instanziierung. Von normalen (nicht-abstrakten) Oberklassen dürfte man durchaus Objekte erzeugen.

3. Was macht protected?

Die Stufe zwischen den beiden: strenger als public, lockerer als private. Passend für Attribute, die Unterklassen brauchen (as x und y in Shape).

4. Circle und Rectangle haben beide ein eigenes draw(). In der Schleife wird f.draw() aufgerufen und jedes Objekt macht seins. Wie heißt das?

Polymorphie = Vielgestaltigkeit: gleicher Methodenaufruf, objektspezifisches Verhalten. Das Finale der OOP-Grundideen.

5. Wozu ruft der Konstruktor einer Unterklasse super(x, y) auf?

super(…) ruft den Konstruktor der Oberklasse auf. Der setzt x und y, der Konstruktor der Unterklasse nur noch radius & Co.
