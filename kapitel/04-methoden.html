Methoden

Denselben Code dreimal schreiben ist nicht fleißig, sondern teuer. Methoden sind die Antwort.

ca. 45 min

DAS PROBLEM

Drei Gäste sollen begrüßt werden. Der Code dafür ist kopiert. Fällt dir in der Ausgabe etwas auf?

Greeting.java

System.out.println("Hello Aylin!");
System.out.println("Nice to have you here, Aylin.");
System.out.println("Hello Mia!");
System.out.println("Nice to have you here, Mia.");
System.out.println("Hello Ben!");
System.out.println("Nice to have you here, Mia.");
KONSOLE

Ben wird als Mia begrüßt: Beim Kopieren blieb ein Name stehen. Und jede Änderung an der Begrüßung müsstest du dreimal machen.

Greeting.java

public class Greeting {

    static void greet(String name) {
        System.out.println("Hello " + name + "!");
        System.out.println("Nice to have you here, " + name + ".");
    }

    public static void main(String[] args) {
        greet("Aylin");
        greet("Mia");
        greet("Ben");
    }

}
KONSOLE

Die Begrüßung steht einmal da und wird dreimal aufgerufen, jedes Mal mit einem anderen Namen. Wie du solche Methoden schreibst, zeigt dieses Kapitel.

4.1 Methodendeklaration und Signatur

Die Lösung: Eine Methode ist ein Stück Code mit Namen. Einmal geschrieben, beliebig oft aufgerufen, jedes Mal mit anderen Werten. (Andere Sprachen sagen Funktion.) Sie arbeitet wie eine kleine Maschine: Hinein gehen Parameter, heraus kommt ein Rückgabewert.

AUFBAU · KLICK AUF EINEN TEIL

static Rückgabetyp name(Typ parameter) {
    Anweisungen
    return Wert;
}

Die erste Zeile heißt Signatur: Sie zeigt, was die Methode braucht und was sie liefert. Kommt nichts zurück, steht dort void, und das return mit Wert fällt weg. Mehrere Parameter trennt ein Komma, ohne Parameter bleiben die Klammern leer.

static steht vorerst vor jeder eigenen Methode, denn die main ist selbst static und kann nur andere static-Methoden direkt aufrufen. Fehlt es, meldet der Compiler beim Aufruf non-static method … cannot be referenced from a static context. Was genau dahintersteckt, steht im Level-Up weiter unten.
Rückgabetyp: der Typ des Werts, den die Methode mit return zurückgibt, etwa int, double, boolean oder String. Bei static double twice(…) ist das Ergebnis jedes Aufrufs ein double.
Name: frei wählbar, beginnt mit einem Kleinbuchstaben und sagt, was die Methode tut, am besten mit einem Verb: twice, sayHello, calculateSum. Unter diesem Namen wird sie aufgerufen.
Parameter: Typ und Name einer Variablen, die erst beim Aufruf ihren Wert bekommt, etwa double number. In der Methode benutzt du sie wie jede andere Variable. Jeder Parameter braucht seinen eigenen Typ: (int a, int b), nicht (int a, b).
Der Methodenrumpf steht zwischen den geschweiften Klammern: die Anweisungen, die bei jedem Aufruf von oben nach unten ausgeführt werden. Hinter die Signatur gehört kein Semikolon, sondern direkt die {.
return gibt den Wert an die Stelle des Aufrufs zurück und beendet die Methode sofort. Anweisungen direkt dahinter werden nie ausgeführt.
Wert: das Ergebnis, das zurückgegeben wird: eine Zahl, eine Variable oder eine Rechnung wie number * 2. Sein Typ muss zum Rückgabetyp passen.

Signatur lesen

static double twice(double number) {
    return number * 2;
}

ZEILE FÜR ZEILE

staticvorerst Pflicht vor jeder Methode. Was es bedeutet, steht im Level-Up weiter unten.
doubleder Rückgabetyp: Die Methode gibt einen Wert dieses Typs zurück, hier eine Kommazahl.
twiceder Name der Methode. Mit ihm wird sie aufgerufen.
(double number)der Parameter: eine Variable, die erst beim Aufruf ihren Wert bekommt.
return number * 2;gibt das Ergebnis zurück und beendet die Methode.

Parameter und Rückgabewert sind optional. Das ergibt genau vier Sorten, hier alle in einem Programm:

Vier Sorten in einem Programm

Klick auf eine Methode oder ihren Aufruf: Beide leuchten gemeinsam auf. Dann „Ausführen“.

Cinema.java

public class Cinema {

    static void greet() {
        System.out.println("Welcome to the cinema!");
    }

    static void showMovie(String title) {
        System.out.println("Now showing: " + title);
    }

    static int freeSeats() {
        return 42;
    }

    static double price(int tickets) {
        return tickets * 8.5;
    }

    public static void main(String[] args) {
        greet();
        showMovie("Zombie Academy");
        int free = freeSeats();
        System.out.println("Free seats: " + free);
        double sum = price(3);
        System.out.println("3 tickets: " + sum + " euros");
    }

}
KONSOLE

Parameter und Rückgabewert sind jeweils optional, das ergibt vier Sorten. Die Methoden stehen neben der main, aufgerufen werden sie in der main.

Sorte 1: nichts hinein, nichts heraus. Rückgabetyp void, leere Klammern. Aufgerufen wird sie als eigene Anweisung: greet();
Sorte 2: etwas hinein, nichts heraus. Der Parameter String title bekommt beim Aufruf den Wert aus den Klammern: showMovie("Zombie Academy"); Rückgabetyp void, also kommt nichts zurück.
Sorte 3: nichts hinein, etwas heraus. Leere Klammern, Rückgabetyp int. Den Rückgabewert speicherst du beim Aufruf in einer Variablen vom selben Typ: int free = freeSeats();
Sorte 4: etwas hinein, etwas heraus. Parameter int tickets, Rückgabetyp double. price(3) rechnet 3 * 8.5 und gibt 25.5 zurück, der Wert landet in sum.
return gibt den Wert dahinter zurück und beendet die Methode. Der Wert muss zum Rückgabetyp passen. Methoden mit void brauchen kein return.
Die main ruft die Methoden der Reihe nach auf. Die Methoden selbst stehen daneben in derselben Klasse, nicht in der main.

Zwei Methoden kennst du schon: main ruft Java automatisch auf, System.out.println(…) rufst du seit Kapitel 2 selbst auf. Neu ist nur: Du baust deine eigenen.

Merk dir das

Signatur lesen: Rückgabetyp · Name · Parameter. void heißt: Es kommt nichts zurück.

Tickets.java: vervollständige das Programm

public class Tickets {

    // gibt nichts zurück, bekommt einen Namen
    static  greet(String name) {
        System.out.println("Hello " + name + "!");
    }

    // bekommt eine Anzahl, gibt den Preis zurück
    static int price( count) {
         count * 8;
    }

    public static void main(String[] args) {
        greet("Mia");
         sum = price(3);
        System.out.println("3 tickets cost " + sum + " euros.");
    }

}

4.2 Methodenaufrufe und Rückgabewerte

Eine Methode läuft erst, wenn jemand sie aufruft: mit ihrem Namen und den Werten in der Klammer. Was sie mit return zurückgibt, fängst du in einer Variable auf oder rechnest direkt damit weiter.

AUFBAU · KLICK AUF EINEN TEIL

name(Argumente);
Typ variable = name(Argumente);

Eigene Methoden schreibst du in dieselbe Klasse wie die main: daneben, nicht hinein. Die erste Zeile ruft eine Methode auf und lässt sie arbeiten, die zweite fängt zusätzlich ihren Rückgabewert auf.

Name der Methode: genau so geschrieben wie in der Signatur, Groß- und Kleinschreibung inklusive. Die runden Klammern gehören zu jedem Aufruf, auch ohne Argumente: rollDie().
Argumente: die Werte für die Parameter, durch Kommas getrennt, etwa "Aylin" oder 2, 3. Anzahl, Reihenfolge und Typen müssen zur Parameterliste passen. Der Typ steht beim Aufruf nicht davor: sayHello("Ben"), nicht sayHello(String "Ben").
Typ der Variablen: muss zum Rückgabetyp der Methode passen. Liefert rollDie() ein int, schreibst du int pips = rollDie();. Eine void-Methode liefert keinen Wert, ihr Aufruf kann deshalb nicht rechts vom = stehen.
Variable: ein frei gewählter Name, unter dem der Rückgabewert gespeichert wird. Danach arbeitest du mit ihr wie mit jeder anderen Variable, etwa System.out.println(pips);.
Das Gleichheitszeichen weist zu: Zuerst wird die Methode ausgeführt, dann wird ihr Rückgabewert in der Variablen links gespeichert.

ZombieApocalypse.java

public class ZombieApocalypse {

    public static void main(String[] args) {
        sayHello("Aylin");        // Aufruf 1
        sayHello("Ben");          // Aufruf 2, gleicher Code, other Wert!
        sayHello("Ben");          // geht auch doppelt. Ben freut sich.
    }

    static void sayHello(String name) {
        System.out.println("Hi, " + name + "!");
    }

}
KONSOLE

ZEILE FÜR ZEILE

sayHello("Aylin");der Aufruf: Java springt in die Methode, der Parameter name bekommt den Wert "Aylin". Danach geht es in der main weiter.
sayHello("Ben");derselbe Code mit einem anderen Wert. Ein Aufruf statt einer Kopie, und das gern auch zweimal.
void sayHello(String name)steht neben der main, nicht in ihr. void: Die Methode gibt etwas aus, zurück kommt nichts.

Ändert sich die Begrüßung, änderst du sie an genau einer Stelle.

Die Regel dahinter heißt DRY, „Don't Repeat Yourself“, wiederhole dich nicht. Gemeint ist nicht „tippe wenig“, sondern: Jedes Stück Wissen steht an genau einer Stelle. Steht der Steckbrief fünfmal im Code, vergisst du beim Ändern irgendwann eine Stelle. Nicht vielleicht: sicher.

Der Sprung-Stepper: Was passiert bei einem Aufruf WIRKLICH?

Das Schwierigste ist unsichtbar: Java springt beim Aufruf in die Methode und danach zurück. Hier in Zeitlupe.

Sprung.java

public static void main(String[] args) {
    int a = twice(5);
    System.out.println(a);
}

static int twice(int x) {
    return x * 2;
}

int a (in main) :
int x (Parameter) :

Bereit. Drück „Schritt“.

Erst du, dann Java

Rückgabewerte kann man weiterverrechnen, direkt im println. Was kommt raus? Notier deine Vermutung, bevor du ausführst.

Square.java (Ausschnitt)

static int square(int x) {
    return x * x;
}

System.out.println(square(3) + 1);      // ???
System.out.println(square(2 + 1));      // ??? (Achtung, Klammern!)
KONSOLE

10 und 9. Bei square(3) + 1 wird erst quadriert (9), dann addiert. Bei square(2 + 1) kommt erst die Klammer (3), dann wird quadriert.

Merk dir das

  • void: Es kommt nichts zurück. Die Methode tut nur etwas (z. B. ausgeben). Speichern kann man nichts, es gibt kein Ergebnis.
  • Typ statt void (z. B. int): Die Methode muss per return einen passenden Wert liefern. Den fängst du auf: int pips = rollDie();
  • Parameter sind Variablen, die beim Aufruf ihren Wert bekommen. Die Werte, die du übergibst, heißen Argumente. Der Compiler prüft ihre Typen so streng wie bei jeder Zuweisung.
  • return beendet die Methode sofort. Code direkt danach lehnt der Compiler ab (unreachable statement).
Level-Up: Was soll dieses static überall?optional

static heißt „gehört fest zur Klasse, funktioniert ohne Vorbereitung“. Die main ist static und kann nur andere static-Methoden direkt aufrufen: deshalb steht es vor jeder Methode. Ein Beispiel aus der Java-Welt: Math.random().

Methoden ohne static gehören einzelnen Objekten und greifen auf deren Daten zu (Kapitel 9).

Und final? Kennst du aus Kapitel 3: Konstanten.

4.3 Gültigkeitsbereich von Variablen

Eine Variable gilt in dem Block { … }, in dem sie deklariert wurde: von ihrer Zeile bis zur schließenden Klammer. Das ist ihr Gültigkeitsbereich. Er erklärt, warum es Parameter und return braucht.

Zone.java

public class Zone {

    static int doubleIt(int value) {
        int result = value * 2;
        return result;
    }

    public static void main(String[] args) {
        int supply = 5;
        System.out.println(doubleIt(supply));
    }

}
KONSOLE

Klick auf eine Variable im Code. Hervorgehoben bleiben die Zeilen, in denen sie gilt: ihr Gültigkeitsbereich.

value ist ein Parameter und gilt in doubleIt, bis zu deren schließender Klammer. Die main kennt ihn nicht. Beim Aufruf bekommt er eine Kopie des Arguments, hier die 5 aus supply.
result gilt ab seiner Deklaration bis zum Ende von doubleIt. Mit return verlässt nur der Wert 10 die Methode, die Variable selbst gibt es draußen nicht.
supply gilt in der main, ab seiner Zeile bis zur schließenden Klammer der main. doubleIt kennt den Namen nicht, rechnet aber mit der 5: Sie wurde als Kopie übergeben.

Merk dir das

Zwischen Methoden gibt es für Werte nur zwei Wege: hinein über die Parameter, heraus über return. Alle anderen Variablen gelten nur in ihrer eigenen Methode.

Aufgabe 4.3.1: Wo gilt was?

Zwei Zeilen mehr, und es übersetzt nicht. Was sagt javac?

Zone.java: two Zeilen mehr

public class Zone {

    static int doubleIt(int value) {
        int result = value * 2;
        return result;
    }

    public static void main(String[] args) {
        int supply = 5;
        int doubled = doubleIt(supply);

        System.out.println(doubled);
        System.out.println(result);
    }

}
JAVAC

Die häufigste Ursache für cannot find symbol (Platz 3 im Panik-Wörterbuch): Der Name ist richtig geschrieben, gilt an dieser Stelle aber nicht.

4.4 Überladen von Methoden

Zwei Methoden dürfen denselben Namen tragen, wenn der Compiler sie an der Parameterliste unterscheiden kann. Das heißt Überladen. Du nutzt es seit Kapitel 2: System.out.println akzeptiert Text, ganze Zahlen, Kommazahlen, boolean. Keine Zauberei: Es gibt println zehnmal, einmal je Sorte.

AUFBAU · KLICK AUF EINEN TEIL

static Typ name(Parameterliste A) { … }
static Typ name(Parameterliste B) { … }

Die Parameterlisten müssen sich in Anzahl, Typen oder Reihenfolge unterscheiden. Welche Fassung läuft, entscheidet der Compiler beim Aufruf an Anzahl und Typ der Argumente.

Rückgabetyp: darf bei beiden Fassungen gleich oder verschieden sein. Er allein unterscheidet sie aber nicht: Zwei Methoden mit gleichem Namen und gleicher Parameterliste lehnt der Compiler ab, auch wenn ihre Rückgabetypen verschieden sind.
Derselbe Name in beiden Zeilen, genau gleich geschrieben. Das ist Überladen: ein Name für dieselbe Aufgabe mit verschiedenen Parametern, etwa add für zwei oder für drei Zahlen.
Parameterliste A: die Parameter der ersten Fassung, etwa int a, int b. Der Aufruf add(2, 3) führt diese Fassung aus.
Parameterliste B: muss sich von A unterscheiden, etwa int a, int b, int c oder double a, double b. Andere Parameternamen allein reichen nicht: int x, int y gilt als dieselbe Liste wie int a, int b.
Der Methodenrumpf { … }: Jede Fassung ist eine vollständige Methode mit eigenem Rumpf. Die Punkte stehen hier nur als Platzhalter für die Anweisungen.

Adder.java (Ausschnitt)

static int add(int a, int b) {
    return a + b;
}

static int add(int a, int b, int c) {
    return a + b + c;
}

static double add(double a, double b) {
    return a + b;
}

ZEILE FÜR ZEILE

add(int a, int b)zwei ganze Zahlen. Läuft bei add(2, 3).
add(int a, int b, int c)drei ganze Zahlen. Läuft bei add(2, 3, 4).
add(double a, double b)zwei Kommazahlen. Läuft bei add(2.5, 3.5).

Merk dir das

  • Es zählt die Parameterliste: Anzahl, Typen, Reihenfolge.
  • Der Rückgabetyp zählt nicht. Unterscheiden sich zwei Methoden nur darin, ist das kein Überladen, sondern ein Übersetzungsfehler.

Warum? Der Compiler wählt die Fassung an der Aufrufstelle, und dort stehen nur die Argumente.

Aufgabe 4.4.1: Welche wird aufgerufen?

Sag die Konsole voraus. Spannend ist die letzte Zeile: Ein add(int, double) gibt es gar nicht.

Adder.java

public class Adder {

    static int add(int a, int b) {
        return a + b;
    }

    static int add(int a, int b, int c) {
        return a + b + c;
    }

    static double add(double a, double b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(add(2, 3));
        System.out.println(add(2, 3, 4));
        System.out.println(add(2.5, 3.5));
        System.out.println(add(2, 3.5));
    }

}
KONSOLE

Beim letzten Aufruf add(2, 3.5) läuft auch die dritte Fassung: Java macht aus der 2 eine 2.0.

Das reicht für jetzt

  • Methode = Code mit Namen: einmal schreiben, beliebig oft aufrufen. Hausregel (DRY): Wer Code kopieren will, schreibt eine Methode.
  • Signatur lesen: Rückgabetyp · Name · Parameter.
  • void = nichts kommt zurück. Sonst liefert return den Wert und beendet die Methode sofort.
  • Rückgabewerte kann man auffangen und weiterverrechnen.
  • Eine Variable gilt nur in ihrem Block. Werte kommen nur über Parameter hinein und über return heraus.
  • Überladen: gleicher Name, andere Parameterliste. Der Rückgabetyp zählt nicht.

Checkpoint

4 Fragen zu Methoden.

1. Was verrät dir static int countZombies() über die Methode?

Rückgabetyp int (vor dem Namen), leere Klammern = keine Parameter.

2. Eine Methode ist als void deklariert. Was folgt daraus?

void = kein Rückgabewert. Die Methode tut etwas, liefert aber nichts. Parameter darf sie trotzdem haben.

3. Gegeben: static void sayHello(String name). Was passiert bei sayHello(42);?

Argumente müssen zu den Parameter-Typen passen. Falscher Typ → das Programm kompiliert erst gar nicht.

4. Was macht return?

return gibt das Ergebnis an den Aufrufer zurück und beendet die Methode. Drucken ist Sache von System.out.println.
