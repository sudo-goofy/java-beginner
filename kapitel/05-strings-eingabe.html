Kapitel 5 von 11 · Fremde Methoden und der Scanner

Strings & Input

Bis hierher hast du Methoden gebaut. Jetzt benutzt du fertige und holst zum ersten Mal einen Wert von außen ins Programm.

ca. 40 min

DAS PROBLEM

Das Programm soll jeden begrüßen, der davorsitzt. Wen begrüßt es?

Greeting.java

String name = "Aylin";
System.out.println("Hello " + name + "!");
KONSOLE

Es begrüßt immer Aylin, egal wer davorsitzt. Der Name steht fest im Code.

Greeting.java

import java.util.Scanner;

public class Greeting {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        System.out.println("What is your name?");
        String name = keyboard.nextLine();
        System.out.println("Hello " + name + "!");
    }

}
KONSOLE

Jetzt fragt das Programm, und der Name kommt von der Tastatur (hier wurde „Mia“ getippt). Wie Eingaben funktionieren und wie du Texte aufbereitest, zeigt dieses Kapitel.

In diesem Kapitel

Danach kannst du
  • fertige Methoden von String benutzen: trim, toUpperCase, charAt, replace
  • erklären, warum input.trim(); allein gar nichts bewirkt
  • mit Scanner einen Wert von der Tastatur einlesen
  • Casten und Parsen auseinanderhalten und parseInt & Co. richtig einsetzen

5.1 Methoden der Klasse String

Die meisten Methoden, die du je benutzt, hat jemand anderes geschrieben. Ein paar stecken in jedem String: Sie zählen Zeichen, entfernen Leerzeichen und ersetzen Text, ohne dass du eine Zeile davon selbst schreibst.

AUFBAU · KLICK AUF EINEN TEIL

text.methode(Argumente)
text.methode().nächste Methode()

Aufgerufen werden sie anders als deine, nämlich auf einem Wert: erst der Wert, dann ein Punkt, dann der Name. Liefert eine Methode wieder einen String, ruft man auf dem gleich die nächste auf, von links nach rechts gelesen.

text: der String, auf dem die Methode aufgerufen wird, meist eine Variable wie raw oder name. Er selbst ändert sich dabei nie: raw.trim(); allein in einer Zeile lässt raw unverändert. Das Ergebnis speicherst du in einer Variablen: String clean = raw.trim();
Der Punkt ist der Punktoperator: Er ruft die Methode auf genau diesem Wert auf. Tippst du in der IDE den Punkt, schlägt sie dir alle Methoden vor, die ein String hat.
methode: der Name der Methode, etwa trim, length oder toUpperCase, genau so geschrieben, Groß- und Kleinbuchstaben eingeschlossen. Die runden Klammern gehören immer dazu, auch wenn sie leer bleiben: raw.length ohne Klammern meldet der Compiler als Fehler.
Argumente: die Werte, die die Methode zum Arbeiten braucht, durch Komma getrennt: charAt(0), replace("felix", "franz"). Braucht sie keine, bleiben die Klammern leer: trim().
nächste Methode: Sie läuft auf dem Rückgabewert der Methode davor. Das heißt Methodenverkettung: Bei raw.trim().toUpperCase() läuft toUpperCase() auf dem String ohne Leerzeichen am Rand. Liefert die Methode davor eine Zahl wie length(), gibt es darauf keine String-Methoden: raw.length().trim() meldet der Compiler als Fehler.

TextTool.java

public class TextTool {

    public static void main(String[] args) {
        String raw = "  Zombiefelix  ";

        System.out.println(raw.length());
        System.out.println(raw.trim());
        System.out.println(raw.trim().length());
        System.out.println(raw.trim().toUpperCase());
        System.out.println(raw.trim().charAt(0));
        System.out.println(raw.trim().replace("felix", "franz"));
    }

}
KONSOLE

ZEILE FÜR ZEILE

raw.length()zählt die Zeichen: 11 Buchstaben und die vier Leerzeichen am Rand, zusammen 15.
raw.trim()liefert denselben Text ohne die Leerzeichen am Anfang und Ende. In raw selbst ändert sich nichts.
raw.trim().toUpperCase()eine Methodenverkettung: Auf dem String, den trim() liefert, läuft gleich toUpperCase().
raw.trim().charAt(0)das Zeichen an Stelle 0, also das erste: Z.
replace("felix", "franz")ersetzt jedes Vorkommen von „felix“ durch „franz“.

Diese sechs reichen für den Anfang:

  • length(): as viele Zeichen? (Leerzeichen zählen mit.)
  • trim(): schneidet Leerzeichen am Anfang und Ende ab.
  • toLowerCase() / toUpperCase(): alles klein, alles groß.
  • charAt(i): das Zeichen an Stelle i. Gezählt wird ab 0.
  • replace(old, replacement): ersetzt jedes Vorkommen.
  • equals(other): Inhalte vergleichen (Kapitel 6).

Erst du, dann Java

Die Stelle, an der es die meisten erwischt: Unten steht input.trim(); allein in einer Zeile, ohne Zuweisung. Was steht danach in input? Der Kasten fragt dich nach der Ausgabe, bevor er sie zeigt.

Immutable.java

public class Immutable {

    public static void main(String[] args) {
        String input = "  YES  ";

        input.trim();
        System.out.println("[" + input + "]");

        String clean = input.trim();
        System.out.println("[" + clean + "]");
    }

}
KONSOLE: die eckigen Klammern zeigen, wo der Text aufhört

Merk dir das

  • Ein String ändert sich nie. trim() schneidet nichts ab, es liefert einen neuen String zurück.
  • Wer diesen Rückgabewert keiner Variablen zuweist, hat umsonst gerechnet. Wie bei deinen eigenen Methoden: Der Rückgabewert muss irgendwo hin.

5.2 Benutzereingabe mit Scanner

Bisher standen alle Werte im Code. Ein Programm, das etwas fragt, muss die Antwort auch lesen können. Das übernimmt der Scanner: Er liest, was jemand auf der Tastatur tippt.

AUFBAU · KLICK AUF EINEN TEIL

import java.util.Scanner;

Scanner tastatur = new Scanner(System.in);
String text = tastatur.nextLine();

Der Import steht ganz oben, über der Klasse, die beiden anderen Zeilen in der main. Drei Zeilen, nur die dritte musst du heute verstehen.

Die Import-Anweisung nennt dem Compiler das Paket, in dem die Klasse Scanner liegt: java.util. Fehlt sie, meldet er bei Scanner den Fehler cannot find symbol. Die IDE fügt die Zeile auf Wunsch selbst ein.
Scanner keyboard deklariert eine Variable vom Typ Scanner. Der Name ist frei wählbar, etwa keyboard oder sc, muss aber vor .nextLine() genauso wieder stehen. Ein Scanner reicht für alle Eingaben des Programms.
new Scanner(System.in) erzeugt ein Scanner-Objekt und verbindet es mit System.in, der Standardeingabe, also der Tastatur. System.in ist das Gegenstück zu System.out. Was new genau tut, kommt in Kapitel 9.
String text deklariert die Variable, in der die Eingabe gespeichert wird. Ihr Typ ist String, denn nextLine() liefert immer Text, auch wenn jemand 17 tippt. Zum Rechnen musst du ihn erst in eine Zahl umwandeln, das Parsen kommt in 5.3.
nextLine() liest die ganze getippte Zeile bis zur Eingabetaste und gibt sie als String zurück. Bis dahin hält das Programm an dieser Stelle an. Leerzeichen am Rand bleiben erhalten, deshalb folgt oft gleich .trim().

Greeting.java

import java.util.Scanner;

public class Greeting {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);

        System.out.println("What is your name?");
        String name = keyboard.nextLine();

        System.out.println("Hello " + name.trim() + ".");
    }

}
KONSOLE: getippt wurde „  Mia  “, mit Leerzeichen

ZEILE FÜR ZEILE

import java.util.Scanner;sagt dem Compiler, wo er die Klasse Scanner findet. Ohne diese Zeile meldet er cannot find symbol.
new Scanner(System.in)erzeugt den Scanner und verbindet ihn mit der Tastatur (System.in ist die Standardeingabe, das Gegenstück zu System.out). Was new tut: Kapitel 9. Bis dahin einfach hinschreiben, wie die main-Zeile.
keyboard.nextLine()der interessante Teil: eine Methode, die die getippte Zeile als String zurückgibt. Diesen Rückgabewert speicherst du in einer Variablen, hier in name.
name.trim()entfernt die Leerzeichen am Rand der Eingabe: Wer „  Mia  “ tippt, bekommt trotzdem „Hello Mia.“ zu lesen.

Merk dir das

Was von der Tastatur kommt, ist roh: Leerzeichen am Rand, Groß- und Kleinschreibung beliebig. Mit den String-Methoden bereitest du alles auf, was von außen kommt, bevor du damit weiterarbeitest.

Level-Up: Die Falle, die jeden einmal erwischtoptional

Für Zahlen gibt es nextInt(). Mischt man es mit nextLine(), wird es seltsam: nextInt() liest die Zahl, aber die Zeilenschaltung vom Enter bleibt ungelesen im Eingabepuffer. Das nächste nextLine() liest diese leere Zeile und ist sofort fertig, ohne zu warten.

Abhilfe: ein einzelnes keyboard.nextLine(); direkt nach dem nextInt(). Den Rückgabewert verwendet man hier absichtlich nicht:

Counter.java

import java.util.Scanner;

public class Counter {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);

        System.out.println("How many zombies?");
        int count = keyboard.nextInt();
        keyboard.nextLine();

        System.out.println("What is the first one called?");
        String name = keyboard.nextLine();

        System.out.println(count + " zombies, the first one is called " + name.trim() + ".");
    }

}
KONSOLE: getippt wurde 3, dann Zombiefelix

Lass keyboard.nextLine(); in deiner IDE versuchsweise weg: Das Programm fragt nach dem Namen und ist im selben Moment fertig.

Zwei Zeilen zum Auswendiglernen, eine zum Verstehen. So ist das mit Bibliotheken: Man benutzt sie, lange bevor man sie durchschaut. Nur so wird überhaupt jemand fertig.

5.3 Casten und Parsen

Mit nextLine() kommt immer Text. Auch wenn jemand 17 tippt, liegt in der Variablen ein String. Rechnen geht damit nicht: raw + 1 hängt nur eine 1 an den Text an. Zwei Wege bringen einen Wert in einen anderen Typ, ähnlich sehen sie sich nur auf den ersten Blick.

AUFBAU · KLICK AUF EINEN TEIL

(Zieltyp) Zahl                 Casten: Zahl in Zahl
Wrapper.parseTyp(Text)      Parsen: Text in Zahl

Die vier Parse-Methoden sind alle gleich gebaut: Wrapper-Klasse, Punkt, parse plus Typ, etwa Integer.parseInt(text).

Die runden Klammern um den Typ sind der Cast-Operator. Er steht direkt vor dem Wert und wandelt ihn in den Typ in der Klammer um. Nötig ist er, wenn dabei etwas verloren gehen kann, etwa von double nach int; von int nach double geht es ohne Cast.
Zieltyp: der Typ, den der Wert bekommen soll, etwa int, long oder double. Von double nach int fallen die Nachkommastellen weg, abgeschnitten, nicht gerundet: (int) 7.9 ergibt 7.
Zahl: der Wert, der umgewandelt wird, eine Zahl oder eine Variable wie number. Der Cast gilt nur für den Wert direkt dahinter: (int) 7.9 * 2 ergibt 14, (int) (7.9 * 2) ergibt 15.
Wrapper-Klasse: die Klasse zum Zieltyp, immer mit großem Anfangsbuchstaben: Integer für int, Double für double, Long für long, Boolean für boolean.
Methodenname: parse, dahinter der Zieltyp mit großem Anfangsbuchstaben. Aus int wird parseInt, aus double wird parseDouble. Es heißt also Integer.parseInt, nicht parseInteger.
Text: der String, aus dem die Zahl gelesen wird, etwa die Eingabe aus nextLine(). Er darf nur die Zahl enthalten, Kommazahlen mit Punkt: "4.99". Bei Integer.parseInt("abc") oder Integer.parseInt(" 17") bricht das Programm mit einer NumberFormatException ab.

Beides in einem Programm: oben geparst, unten gecastet. Getippt wird 17:

Input.java

import java.util.Scanner;

public class Input {

    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);

        System.out.println("How old are you?");
        String raw = keyboard.nextLine();
        int age = Integer.parseInt(raw);
        System.out.println("Next year: " + (age + 1));

        double number = 7.9;
        System.out.println("Cast: " + (int) number);
    }

}
KONSOLE

ZEILE FÜR ZEILE

String raw = keyboard.nextLine();liest die getippte Zeile. Auch 17 kommt hier als Text an.
Integer.parseInt(raw)parst: Die Ziffern im Text werden als Zahl gelesen. In age steht danach der int 17.
(age + 1)rechnet 17 + 1 = 18. Die Klammern sorgen dafür, dass erst gerechnet und dann an den Text gehängt wird.
(int) numbercastet: Der double 7.9 wird zum int, die Nachkommastellen fallen weg. Heraus kommt 7, abgeschnitten, nicht gerundet.

Merk dir das

(int) "42" übersetzt nicht. Ein Cast wandelt nur zwischen Zahlentypen um, einen Text kann er nicht in eine Zahl umwandeln. Dafür gibt es das Parsen.

Aufgabe 5.3.1: Casten oder Parsen?

int b = (int) "7";

incompatible types: String cannot be converted to int. Richtig: Integer.parseInt("7").

int d = Integer.parseInt("four");

NumberFormatException, ein Laufzeitfehler. Abfangen kannst du ihn: Kapitel 11.

int e = (int) 'A';

Ein char ist intern eine Zahl. Deshalb darf man casten, und deshalb ergibt 'A' + 1 die 66.

nextInt() nimmt dir das Parsen ab: lesen und wandeln in einem Schritt. Mit nextLine() plus parseInt behältst aber du die Kontrolle. Und wenn dort twelve steht? Kapitel 11.

Das reicht für jetzt

  • Fertige Methoden ruft man auf einem Wert auf: Wert, Punkt, Name, etwa raw.trim().
  • Für den Anfang: length(), trim(), toUpperCase() / toLowerCase(), charAt(i) (ab 0), replace(old, replacement).
  • Ein String ändert sich nie. Die Methoden liefern einen neuen zurück: Rückgabewert einer Variablen zuweisen, sonst geht er verloren.
  • Scanner: importieren, mit new Scanner(System.in) erzeugen, mit nextLine() lesen.
  • Was von außen kommt, ist roh: erst mit trim() und Co. aufbereiten, dann weiterverwenden.
  • Casten wandelt Zahl in Zahl, Parsen Text in Zahl: Integer.parseInt(raw).

Checkpoint

2 Fragen. Beide sind Fallen, in die fast alle einmal tappen.

5. String input = " YES ";, danach steht allein die Zeile input.trim();. Was steht jetzt in input?

Der Rückgabewert muss irgendwo hin, wie bei deinen eigenen Methoden. Richtig wäre input = input.trim();. Sonst geht er verloren.

6. Ein Programm liest mit Scanner von der Tastatur. Die Zeile import java.util.Scanner; fehlt. Was passiert?

Der Import sagt dem Compiler, wo er die Klasse Scanner findet. Fehlt er, kennt der Compiler den Namen Scanner nicht, genau wie bei system statt System. Steht auch im Panik-Wörterbuch.
