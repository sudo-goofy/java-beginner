2.1 Aufbau eines Java-Programms

Jedes Java-Programm steht im selben Gerüst: außen eine Klasse, darin die main-Methode, in der das Programm startet. Was es tun soll, steht als Anweisung in der main.

AUFBAU · KLICK AUF EINEN TEIL

public class {Klassenname} {

    public static void main(String[] args) {
        {Anweisungen}
    }

}

Die Datei heißt genau wie die Klasse, für HelloWorld also HelloWorld.java. Der Rest des Gerüsts ist jedes Mal gleich.

public class leitet die Klasse ein. Jedes Java-Programm steht in einer Klasse. public heißt: von überall erreichbar, auch für die JVM.
Klassenname: frei wählbar, beginnt mit einem Großbuchstaben, ohne Leerzeichen, etwa HelloWorld. Die Datei muss genauso heißen: HelloWorld.java, sonst meldet der Compiler einen Fehler.
Die äußeren Klammern markieren Anfang und Ende der Klasse. Geschweifte Klammern stehen immer paarweise: Zu jeder { gehört eine }.
Die main-Methode: Hier beginnt die JVM das Programm. Die Zeile ist jedes Mal gleich, schreib sie auswendig oder lass sie von der IDE ergänzen. Was die einzelnen Wörter bedeuten, steht im Level-Up weiter unten.
Die inneren Klammern markieren Anfang und Ende der main-Methode. Alles dazwischen läuft beim Start.
Anweisungen: was das Programm tun soll, von oben nach unten, jede mit ; am Ende. Zum Beispiel System.out.println("Hello World!");

HelloWorld.java

public class HelloWorld {

    public static void main(String[] args) {
        System.out.println("Hello World!");
    }

}
KONSOLE

Sieben Zeilen für einen Satz? Ja. Java ist förmlich, wie eine E-Mail, die mit „Sehr geehrte Damen und Herren“ beginnt, nur um „ok“ zu sagen. Aber jede Zeile hat einen Job:

ZEILE FÜR ZEILE

public class HelloWorldJedes Java-Programm steht in einer Klasse, hier mit dem Namen HelloWorld. Die Datei muss dann HelloWorld.java heißen.
public static void main(…)Die main-Methode, der Einstiegspunkt: Die JVM sucht genau diese Methode und beginnt dort mit der Ausführung. Einfach auswendig hinschreiben, das machen Profis auch.
System.out.println("…")Die Output: „System, gib auf dem Ausgabekanal (out) eine Zeile aus (println).“ Text steht immer in doppelten Anführungszeichen.
;Das Semikolon beendet jede Anweisung, wie der Punkt am Satzende.
{ }Geschweifte Klammern markieren Anfang und Ende eines Blocks, hier der Klasse und der main-Methode. Immer im Doppelpack.

Merk dir das

Ein Java-Programm steht in einer Klasse und startet in der main-Methode. Die Datei heißt wie die Klasse: HelloWorld.java.

Level-Up: Was heißt eigentlich „public static void main“?optional

Jedes Wort hat eine feste Bedeutung:

  • public: von überall aufrufbar, auch von der JVM beim Start
  • static: gehört zur Klasse selbst, kein Objekt nötig (Kapitel 4 & 9)
  • void: die Methode gibt nichts zurück (Kapitel 4)
  • main: der feste Name, nach dem die JVM beim Start sucht
  • String[] args: Texte, die man beim Start mitgeben kann, als Array (Kapitel 8)

Einfach auswendig hinschreiben. Profis lassen sie sich automatisch vervollständigen.

Code-Puzzle: Ein gültiges Java-Programm, nur durchgeschüttelt. Sortiere die Zeilen mit den Pfeilen. (Die Einrückung hilft!)

Projekt und Klasse anlegen: Schritt für Schritt

Ein Projekt anlegen

Ein Projekt ist nur ein Ordner mit Ansage: Hier drin liegt Java-Code, und zwar in src. Für dieses Skript reicht eins, etwa mit dem Namen ZombieApocalypse: Darin bekommt jedes Programm seine eigene Klasse.

VS Code

  1. Befehlspalette: Java: Create Java Project.
  2. Als Bauwerkzeug No build tools wählen. Maven und Gradle kommen später im Beruf, jetzt wären sie nur im Weg.
  3. Ordner aussuchen, Name ZombieApocalypse. VS Code legt src gleich mit an.

IntelliJ IDEA

  1. File → New → Project, links Java auswählen.
  2. Als Build system die Einstellung IntelliJ lassen, Maven und Gradle kommen später im Beruf.
  3. Name ZombieApocalypse, JDK auswählen, anlegen. Der Code gehört in src.

Eine Klasse anlegen

Jede Klasse steht in ihrer eigenen Datei, und die Datei heißt exakt wie die Klasse, Zombie also in Zombie.java. Sonst meldet der Compiler einen Fehler; die Meldung dazu steht im Panik-Wörterbuch.

VS Code

  1. Rechtsklick auf den Ordner src, dann New File.
  2. Name mit Endung eintippen: Zombie.java. Die Endung vergisst man genau einmal.
  3. In der leeren Datei class tippen und Tab drücken, die IDE ergänzt das Gerüst.

IntelliJ IDEA

  1. Rechtsklick auf den Ordner src, dann New → Java Class.
  2. Name ohne Endung eintippen: Zombie. Die Datei legt IntelliJ passend an.
  3. Im Klassenrumpf main tippen und Tab drücken, die IDE ergänzt die main-Methode.

Alle acht Handgriffe (starten, stoppen, umbenennen …) stehen auf der Werkzeugseite.

2.2 Syntaxregeln: Semikolon, Klammern, Groß- und Kleinschreibung

Am Anfang haben fast alle Fehlermeldungen dieselben drei Ursachen. Wer diese drei Regeln kennt, erkennt die meisten Fehler, bevor der Compiler sie meldet.

Merk dir das

  1. Jede Anweisung endet mit Semikolon ;, vergessen = Fehler.
  2. Groß-/Kleinschreibung zählt. System funktioniert, system kennt Java nicht.
  3. Geschweifte Klammern { } kommen immer im Doppelpack. Jede geöffnete Klammer will wieder zu.

Aufgabe 2.2.1: Fehler-Jagd

Dieses Programm kompiliert nicht. Klick auf die falschen Stellen. (Falsche Klicks kosten nur Stolz.)

Broken.java

public Class Broken {

    public static void main(String[] args) {
        system.out.println("Works on my machine!")   
        System.out.println("Or maybe not?");
     

}

Gefundene Fehler: 0 von 4

Tipp: Vier Fehler, aber nur drei Regeln von oben: Eine wird zweimal gebrochen.

2.3 Bezeichner und Namenskonventionen

Der Compiler übersetzt jeden erlaubten Namen. Für Menschen, die den Code lesen, reicht das nicht. Deshalb gibt es Konventionen: Regeln ohne Fehlermeldung, aber trotzdem verbindlich.

WasWieBeispiel
Klasseerster Buchstabe groß, jedes weitere Wort auch (PascalCase) HelloWorld, ZombieApocalypse
Variable, Methodeerster Buchstabe klein, jedes weitere Wort groß (camelCase) age, maxWeight, makeSound()
Konstantealles groß, Wörter mit Unterstrich getrennt MAX_RESIDENTS, VAT

Eine Konstante darf sich nie mehr ändern, erkennbar am final davor: static final double VAT = 0.19;. Mehr zu static und final in Kapitel 4, die Großschreibung gilt ab sofort.

Merk dir das

Bei Klassen ist es mehr als Konvention: Die Datei heißt genau wie die öffentliche Klasse darin. HelloWorld steht in HelloWorld.java, Groß- und Kleinschreibung inklusive. Klasse umbenannt, Datei vergessen? Dann klingt die Fehlermeldung nach etwas ganz anderem.

Und: Der Name sagt, was drin ist. int a ist erlaubt und trotzdem falsch, sobald jemand anderes den Code liest, dein zukünftiges Ich eingeschlossen.

Aufgabe 2.3.1: Namen geradeziehen

Wie heißt die Klasse richtig: public class zombieList?

Und die Datei muss dann auch Zombieliste.java heißen.

Wie heißt die Konstante richtig: static final double vat = 0.19;?

Konstanten schreibt man ganz groß, mehrere Wörter mit Unterstrich: MAX_RESIDENTS.

2.4 Ausgabe, Kommentare und Escape-Sequenzen

println gibt eine ganze Zeile aus. Mit print setzt du eine Zeile aus mehreren Stücken zusammen, mit Sonderzeichen bringst du Umbrüche und Anführungszeichen mitten in einen Text, und Kommentare sind Notizen, die Java überliest.

AUFBAU · KLICK AUF EINEN TEIL

System.out.println(was ausgegeben wird);
System.out.print(was ausgegeben wird);

println heißt „print line“: ausgeben, dann Zeilenumbruch. print() ohne „ln“ lässt den Umbruch weg, die nächste Ausgabe steht direkt dahinter.

System.out ist der Standard-Ausgabekanal: die Konsole. Groß geschriebenes S, sonst kennt der Compiler den Namen nicht.
println („print line“) gibt aus und beendet die Zeile. Die nächste Ausgabe beginnt in einer neuen Zeile.
print gibt aus, ohne die Zeile zu beenden. Die nächste Ausgabe steht direkt dahinter.
Was ausgegeben wird: ein Text in doppelten Anführungszeichen wie "Hello", eine Zahl wie 42 oder eine Rechnung wie 1 + 1. Text erscheint genau so, wie er zwischen den Anführungszeichen steht.
Das Semikolon beendet die Anweisung. Fehlt es, meldet der Compiler ';' expected.

Der Computer arbeitet stur von oben nach unten. Die Ausgaben kommen genau in dieser Reihenfolge:

DayPlan.java

public class DayPlan {

    public static void main(String[] args) {
        System.out.println("Line 1: Make coffee");
        System.out.println("Line 2: Write code");
        System.out.println("Line 3: Be puzzled");
        System.out.println("Line 4: Refill coffee");
    }

}
KONSOLE

Erst du, dann Java

Jetzt du: print und println gemischt. Sag die Ausgabe voraus, bevor du sie siehst. So etwas kommt gern in Tests dran.

Verwirrung.java

System.out.print("Java");
System.out.print("Script?");
System.out.println();
System.out.println("No.");
KONSOLE

ZEILE FÜR ZEILE

System.out.print("Java");gibt Java aus. Kein Umbruch: Die nächste Ausgabe landet in derselben Zeile.
System.out.print("Script?");klebt direkt dahinter. Jetzt steht JavaScript? in der Zeile.
System.out.println();gibt keinen Text aus, nur den Zeilenumbruch.
System.out.println("No.");steht deshalb in der zweiten Zeile und bricht danach selbst um.
Level-Up: Sonderzeichen in Texten (Escape-Sequenzen)optional

Manche Zeichen passen nicht direkt in einen String. Dafür gibt es den Backslash \:

  • \n: Zeilenumbruch mitten im Text
  • \": ein Anführungszeichen im Text (sonst hält der Compiler den String dort für beendet)
  • \\: ein echter Backslash

Escape.java (Ausschnitt)

System.out.println("He said: \"Java is fun\"\nHonestly.");
System.out.println("Path: C:\\Program Files\\Java");
KONSOLE
Level-Up: Kommentare: Notizen, die Java überliestoptional

Mit // schreibst du Notizen nur für Menschen. Java ignoriert sie komplett:

Kommentare.java (Ausschnitt)

// Das hier ist ein Kommentar. Java tut so, als wäre es Luft.
System.out.println("I am code.");    // geht auch hinter einer Anweisung

/* Und so kommentiert man
   gleich mehrere Zeilen am Stück. */
System.out.println("Me too.");
KONSOLE: was erscheint, was nicht?

Wenige, aber gute Kommentare: Sie erklären das Warum, nicht das Offensichtliche.

Merk dir das

print klebt, println bricht um. Kommentare (//) überliest der Compiler. Sonderzeichen im Text beginnen mit Backslash: \n für einen Umbruch, \" für ein Anführungszeichen.

Aufgabe 2.4.1: Ausgabe-Werkstatt

Neun Anweisungen untereinander in einer main. Schreib die komplette Konsole auf, bevor du ausführst. Wo entsteht ein Umbruch, wo nicht?

Output.java

public class Output {

    public static void main(String[] args) {
        System.out.println("Hello");
        System.out.print("Hello");
        System.out.println("A" + "B");
        System.out.println(1 + 2);
        System.out.println("1" + 2);
        System.out.println("Line1\nLine2");
        System.out.println("He said \"Hello\".");
        System.out.println();
        System.out.println("End");
    }

}
KONSOLE
Die drei Stellen, an denen es hakt
  • Zeile 2 macht keinen Umbruch. print ohne „ln“, also steht das AB aus Zeile 3 direkt dahinter: HelloAB.
  • 1 + 2 rechnet, "1" + 2 verkettet. Sobald ein String beteiligt ist, addiert + nicht mehr, sondern verkettet.
  • \n und \" sind Escape-Sequenzen. Das eine macht einen Umbruch, das andere ein Anführungszeichen, beide im Text.

Die vorletzte Zeile ist wirklich leer: println() ohne Text gibt nur den Umbruch aus.

Das reicht für jetzt

  • Ein Java-Programm steht in einer Klasse und startet in der main-Methode.
  • System.out.println("…") gibt Text aus. print klebt, println bricht um.
  • 90 % der Anfängerfehler: Semikolon vergessen, Groß-/Kleinschreibung verwechselt, Klammer nicht geschlossen.
  • Klassen in PascalCase, Variablen in camelCase, Konstanten ganz groß (VAT).
  • Die Datei heißt wie die Klasse: HelloWorld.java.
  • Kommentare (//) überliest der Compiler. Sonderzeichen im Text: \n, \".

Checkpoint

4 Fragen zu Klasse, main und Ausgabe.

1. Wo startet jedes Java-Programm?

Die JVM sucht beim Start immer exakt nach public static void main(String[] args). Kein main, kein Start.

2. Was ist an dieser Zeile falsch? system.out.println("Hi");

Java unterscheidet streng zwischen Groß- und Kleinschreibung. System ist eine Klasse, system kennt Java nicht.

3. Was macht das ; am Zeilenende?

Ohne Semikolon weiß der Compiler nicht, wo die Anweisung aufhört. Das Dach ^ in der Meldung steht direkt hinter dem letzten Zeichen der Zeile, in der es fehlt.

4. Was ist der Unterschied zwischen print() und println()?

„ln“ = line. println springt danach in die nächste Zeile, print bleibt in derselben Zeile.
