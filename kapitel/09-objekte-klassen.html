Mia hat Hunger 7? Name und Hunger gehören nur über die Nummer im Variablennamen zusammen, und eine falsche Nummer fällt niemandem auf.

9.1 Klasse und Objekt

Programme bilden die echte Welt ab: Kunden, Bestellungen, Ampeln, Zombies. Die besteht nicht aus einzelnen ints und Strings, sondern aus Dingen mit mehreren Eigenschaften. Eine Klasse fasst diese Eigenschaften zu einem Bauplan zusammen.

  • Eine Klasse ist ein Bauplan: Sie beschreibt, welche Eigenschaften (Attribute) und Fähigkeiten (Methoden) eine Type von Dingen hat. Etwa: „Jeder Zombie hat Name, Farbe und Laune.“
  • Ein Objekt ist ein konkretes Exemplar nach diesem Bauplan: dieser eine Zombie namens Zombiefelix, orange, hungrig.

Wie Keksausstecher (Klasse) und Kekse (Objekte): ein Ausstecher, beliebig viele Kekse, jeder anders verziert.

Nochmal anders erklärt: das Formularoptional

Ein leeres Anmeldeformular beim Zombie-Abwehr-Zentrum hat vorgedruckte Felder: Name: ___, Farbe: ___, Laune: ___. Es ist noch kein Zombie, sagt aber, welche Angaben es zu einem Zombie gibt.

  • Klasse = der leere Vordruck (definiert die Felder)
  • Objekt = ein ausgefülltes Exemplar (Name: Zombiefelix, Farbe: orange, …)
  • new = „einmal den Vordruck kopieren und ausfüllen, bitte!“

Vom selben Vordruck kann es hunderte ausgefüllte Formulare geben, jedes mit anderen Angaben.

AUFBAU · KLICK AUF EINEN TEIL

public class Klassenname {
    Typ attribut;
    Typ attribut;
}

Klassenname variable = new Klassenname();
variable.attribut = Wert;

Die Attribute stehen in der Klasse, aber in keiner Methode. Die unteren beiden Zeilen stehen in der main einer anderen Klasse.

Klassenname: beginnt mit einem Großbuchstaben, etwa Zombie, und die Datei heißt genauso: Zombie.java. In der unteren Zeile steht er zweimal: vorn als Typ der Variable, hinter new als die Klasse, von der ein Objekt erzeugt wird.
Typ: der Datentyp des Attributs, etwa String für Text oder int für ganze Zahlen. Er legt fest, welche Werte das Attribut aufnehmen kann.
Attribut: eine Eigenschaft, die jedes Objekt der Klasse hat, klein geschrieben, etwa name oder mood. Jedes Objekt hat dafür seinen eigenen Wert. Solange du keinen setzt, steht in einem String-Attribut null.
Variable: speichert eine Referenz auf das neue Objekt, etwa felix. Ihr Typ ist die Klasse. Über diesen Namen erreichst du das Objekt danach, wie in der letzten Zeile vor dem Punkt.
new erzeugt ein neues Objekt der Klasse, mit eigenen Werten für alle Attribute. Die runden Klammern dahinter gehören dazu: new Zombie(). Zweimal new heißt zwei voneinander unabhängige Objekte.
Der Punkt-Operator greift auf ein Attribut eines bestimmten Objekts zu: felix.name heißt „das Attribut name von felix“. Links vom = schreibst du so einen Wert hinein, mit System.out.println(felix.name); liest du ihn aus.
Wert: was ins Attribut geschrieben wird. Er muss zum Typ passen: "Zombiefelix" in Anführungszeichen für einen String, 3 ohne Anführungszeichen für einen int.

Die einfachste Klasse der Welt

Ganz minimal: eine Klasse, die nur beschreibt, was jeder Zombie hat:

Zombie.java: Version 1, nur Attribute

public class Zombie {

    // Attribute: Was hat jeder Zombie?
    String name;
    String color;
    String mood;

}

Das war's: eine Klasse nur mit Attributen, ohne main. Ausführen kann man sie nicht. Benutzt wird sie von einer ausführbaren Klasse mit main:

ZombieApocalypse.java, die ausführbare Klasse

public class ZombieApocalypse {

    public static void main(String[] args) {
        Zombie felix = new Zombie();     // new erzeugt ein Objekt der Klasse

        felix.name = "Zombiefelix";      // Punkt-Operator: Attribut befüllen
        felix.color = "orange";
        felix.mood = "hungry";

        System.out.println(felix.name);   // … und auslesen
        System.out.println(felix.color);
    }

}

String name;ein Attribut: Jeder Zombie bekommt sein eigenes Feld name. Noch steht nichts darin.
Zombie felix = new Zombie();new erzeugt ein Objekt der Klasse Zombie. Erreichbar ist es über die Variable felix, ihr Typ ist die Klasse.
felix.name = "Zombiefelix";der Punkt-Operator: Das Attribut name von felix bekommt einen Wert.
System.out.println(felix.name);liest das Attribut über den Punkt wieder aus und gibt Zombiefelix aus.

Attribute ohne Wert

Erst du, dann Java

Version 1 hat einen Haken. Was passiert, wenn man das Befüllen vergisst?

ZombieApocalypse.java: hoppla

Zombie mia = new Zombie();      // Objekt gebaut …
                              // … aber niemand hat die Attribute gesetzt!
System.out.println(mia.name); //  ???
KONSOLE: was kommt wohl raus?

null heißt „da ist nichts“. Das Objekt mia existiert, aber niemand hat seine Attribute gesetzt. Objekte mit ungesetzten Attributen sind eine der häufigsten Fehlerquellen:

  • Noch stürzt nichts ab, println(mia.name) zeigt nur null.
  • Machst du etwas mit dem Namen, etwa mia.name.length(), wirft Java die berüchtigte NullPointerException (Panik-Wörterbuch).

Merk dir das

Der Punkt-Operator heißt „von“: felix.name = „der Name von felix“. Lesen und Schreiben gehen über den Punkt.

9.2 Konstruktoren

Besser wäre, man könnte ein Objekt gar nicht erst ohne Werte erzeugen. Dafür gibt es den Konstruktor: Er läuft bei jedem new und legt fest, welche Werte man dabei angeben muss.

AUFBAU · KLICK AUF EINEN TEIL

public Klassenname(Typ parameter, …) {
    this.attribut = parameter;
}

Klassenname variable = new Klassenname(Wert, …);

Der Konstruktor heißt exakt wie die Klasse und hat keinen Rückgabetyp, nicht einmal void. new ruft ihn auf und gibt ihm die Werte in derselben Reihenfolge mit.

Klassenname: Oben ist er der Name des Konstruktors, etwa public Zombie(…) in der Klasse Zombie. Unten steht er als Typ der Variable und hinter new. Schreibst du void vor den Konstruktor, wird daraus eine gewöhnliche Methode, und der Compiler meldet bei new Zombie("Mia", …) einen Fehler.
Typ: der Datentyp des Parameters, meist derselbe wie beim Attribut, das er füllt: String name für das Attribut String name;.
Parameter: nimmt einen Wert entgegen, den der Aufruf mit new mitgibt, und heißt meist wie das Attribut, etwa name. Rechts vom = wird sein Wert ins Attribut geschrieben. Mehrere Parameter trennt ein Komma, jeder ist eine Pflichtangabe.
this steht für das Objekt, das gerade erzeugt wird: this.name ist sein Attribut, name allein der Parameter. Lässt du this. weg, weist name = name; den Parameter sich selbst zu, und das Attribut bleibt null, ohne dass der Compiler etwas meldet.
Attribut: eines der Attribute, die oben in der Klasse deklariert sind. Der Konstruktor gibt ihm seinen Startwert, für jedes Attribut eine Zeile wie diese.
Variable: speichert die Referenz auf das neue Objekt, etwa felix. Ihr Typ ist die Klasse.
Werte: Der erste geht an den ersten Parameter, der zweite an den zweiten, und jeder muss zum Typ seines Parameters passen: new Zombie("Mia", "gray", "relaxed"). Gibt es nur diesen Konstruktor, meldet der Compiler bei new Zombie() ohne Werte einen Fehler.

Zombie.java: Version 2, mit Konstruktor

public class Zombie {

    String name;
    String color;
    String mood;

    // Der Konstruktor: OHNE diese drei Angaben gibt es keinen Zombie!
    public Zombie(String name, String color, String mood) {
        this.name = name;      // "MEIN name = der Wert, der reinkam"
        this.color = color;
        this.mood = mood;
    }

}

ZEILE FÜR ZEILE

public Zombie(String name, …)der Konstruktor: heißt wie die Klasse, kein Rückgabetyp. Seine Parameter sind die Pflichtangaben.
this.name = name;this = „dieses Objekt hier“. this.name ist das Attribut dieses Objekts, name der Parameter, also der Wert, der übergeben wurde.
new Zombie("Mia", …)ruft den Konstruktor auf. „Mia“ landet in name, „gray“ in color, „relaxed“ in mood.
// Zombie geist = new Zombie();ist auskommentiert, denn ohne die drei Pflichtangaben wäre die Zeile ein Compiler-Fehler.

Merk dir das

Drei Vokabeln, ein Satz: new erzeugt das Objekt und ruft den Konstruktor, der die Attribute gleich setzt, und der Punkt-Operator (felix.name) greift danach auf Attribute und Methoden zu. Das sind 80 % der Objektorientierung. Ehrlich.

Level-Up: Wozu genau das „this“ im Konstruktor?optional

this.name = name; sieht doppelt gemoppelt aus. Parameter und Attribut heißen beide name, und this („dieses Objekt hier“) löst die Verwechslung auf:

this erklärt

this.name = name;
// ^^^^^^^   ^^^^
// Attribut  Parameter (der Wert, der reinkam)
// "MEIN name soll der übergebene name sein"

Ohne this. verdeckt der gleichnamige Parameter das Attribut (Gültigkeit, Kapitel 4). name = name; weist dann den Parameter sich selbst zu, das Attribut bleibt unberührt. Der Compiler meldet nichts, die Zeile ist ja formal richtig.

Man könnte den Parameter anders nennen und auf this verzichten, aber die this-Schreibweise ist Standard.

Level-Up: Überladene Konstruktorenoptional

Eine Klasse darf mehrere Konstruktoren haben, wenn sich die Parameterlisten unterscheiden: Überladen (overloading).

Zombie.java (Ausschnitt)

public Zombie(String name, String color, String mood) {
    this.name = name;
    this.color = color;
    this.mood = mood;
}

public Zombie(String name) {              // Kurzversion!
    this.name = name;
    this.color = "gray";                  // Standardwerte
    this.mood = "relaxed";
}

Java erkennt an den Argumenten, welcher Konstruktor gemeint ist: new Zombie("Mia") → Kurzversion, new Zombie("Zombiefelix", "orange", "hungry") → Vollversion.

9.3 Objektmethoden

In Kapitel 4 standen deine Methoden neben der main. Meist gehören sie aber in die Klasse der Objekte: Dort dürfen sie die Attribute des Objekts benutzen und beschreiben, was jeder Zombie kann.

AUFBAU · KLICK AUF EINEN TEIL

public class Klassenname {
    Rückgabetyp methode(Parameter) {
        Anweisungen, die die Attribute benutzen
    }
}

variable.methode(Argumente);

Aufgerufen wird die Methode an einem Objekt, mit dem Punkt-Operator: erst das Objekt, dann der Name der Methode.

Klassenname: die Klasse, zu der die Methode gehört, etwa Zombie. Die Methode steht im Klassenrumpf neben Attributen und Konstruktor, nie innerhalb einer anderen Methode.
Rückgabetyp: der Typ des Werts, den die Methode mit return zurückgibt, oder void, wenn sie nichts zurückgibt: void groan(). Davor steht hier kein static, denn die Methode gehört zu jedem einzelnen Objekt.
Methodenname: klein geschrieben, meist ein Verb, etwa groan. Beim Aufruf unten steht derselbe Name, danach immer runde Klammern, auch wenn sie leer bleiben.
Parameter: Werte, die die Methode beim Aufruf zusätzlich braucht, jeweils mit Typ, etwa double amount. Die Attribute des Objekts gehören nicht hierher, die kennt die Methode schon. Braucht sie nichts, bleiben die Klammern leer.
Anweisungen: der Methodenrumpf. Hier benutzt du die Attribute direkt mit ihrem Namen, ohne Punkt: System.out.println(name + " groans: Grrr!");. Gemeint ist immer das Attribut des Objekts, an dem die Methode gerade aufgerufen wird.
Variable: die Referenz auf das Objekt, an dem die Methode aufgerufen wird. Bei felix.groan() ist name im Rumpf „Zombiefelix“, bei mia.groan() „Mia“.
Argumente: die Werte für die Parameter, in derselben Reihenfolge und mit passendem Typ, etwa account.deposit(20). Ohne Parameter bleiben die Klammern leer: felix.groan();.

Zombie.java (Ausschnitt) + Aufruf

public class Zombie {

    String name;
    // … Konstruktor wie oben …

    void groan() {                  // KEIN static, die Methode gehört zum Objekt!
        System.out.println(name + " groans: Grrr!");
    }

}

// Aufruf über den Punkt-Operator, "groan von felix":
felix.groan();     //  Zombiefelix stöhnt: Grrr!
mia.groan();       //  Mia stöhnt: Grrr!

ZEILE FÜR ZEILE

void groan()eine Methode in der Klasse Zombie, ohne static und ohne Parameter.
name + " groans: Grrr!"benutzt das Attribut name des Objekts, an dem die Methode gerade aufgerufen wird.
felix.groan();gelesen „groan von felix“: Hier ist name also „Zombiefelix“.
mia.groan();dieselbe Methode an einem anderen Objekt, darum mit „Mia“.

Merk dir das

Neu gegenüber Kapitel 4:

  • Kein static: Die Methode gehört jedem einzelnen Objekt, nicht der Klasse als Ganzes.
  • Kein name-Parameter: Jeder Zombie kennt seinen eigenen Namen. Gleicher Aufruf, persönliche Antwort.

9.4 Datenkapselung: Zugriffsmodifikatoren, Getter und Setter

Bisher konnte jeder von außen felix.mood = "exploding" setzen, auch wenn das keine gültige Laune ist. Die Lösung heißt Datenkapselung: Attribute privat machen, Zugriff nur über Methoden.

Zwei Schlüsselwörter regeln, wer worauf zugreifen darf:

  • private: Nur Code in der eigenen Klasse kommt heran.
  • public: Von überall aus benutzbar.
  • Von außen geht es deshalb nur über Methoden: Getter geben einen Wert zurück, Setter ändern ihn und prüfen vorher, ob der neue Wert gültig ist.

AUFBAU · KLICK AUF EINEN TEIL

private Typ attribut;

public Typ getAttribut() {
    return attribut;
}

public void ändern(Typ wert) {
    if (wert ist gültig) {
        attribut = neuer Wert;
    }
}

Der Getter heißt wie das Attribut, mit get davor. Die Methode, die ändert, prüft zuerst und ändert nur, wenn alles stimmt.

private: Nur Code in derselben Klasse kommt an das Attribut heran. Schreibt eine andere Klasse account.balance, meldet der Compiler einen Fehler. Von außen geht es nur über die Methoden darunter.
Typ: steht dreimal und ist jedes Mal derselbe, etwa double: als Typ des Attributs, als Rückgabetyp des Getters und als Typ des Parameters.
Attribut: der Name des geschützten Attributs, etwa balance. Innerhalb der Klasse benutzen die Methoden es direkt mit seinem Namen, ohne Punkt.
public: Die Methode ist von überall aufrufbar, auch aus anderen Klassen, etwa account.getBalance() in der main. Über diese Methoden läuft jeder Zugriff von außen.
Getter: Hinter get steht der Attributname mit großem Anfangsbuchstaben, aus balance wird getBalance(). Er hat keine Parameter, gibt mit return den Wert des Attributs zurück und ändert nichts.
Name der ändernden Methode: sagt, was sie tut, etwa deposit. Setzt sie ein Attribut direkt auf einen neuen Wert, heißt sie meist set plus Attributname, etwa setMood, und man nennt sie Setter. Ihr Rückgabetyp ist void.
Wert und neuer Wert: Der Parameter bringt den gewünschten Wert mit, etwa double amount. Unten wird daraus der neue Wert des Attributs, direkt übernommen oder damit berechnet: balance = balance + amount;.
Die Prüfung: eine Bedingung, die ungültige Werte abfängt, etwa amount > 0. Ist sie false, wird der Block übersprungen, und das Attribut bleibt, wie es war. Kein Semikolon direkt hinter if (…), sonst läuft der Block immer.

Account.java, gut gekapselt

public class Account {

    private double balance;          // private: nur in Konto zugreifbar

    public double getBalance() {     // Getter: liefert den Wert nach außen
        return balance;
    }

    public void deposit(double amount) {   // Änderung beantragen
        if (amount > 0) {                    // WENN der Betrag okay ist …
            balance = balance + amount;          // … DANN wird geändert
        }
    }

}

ZEILE FÜR ZEILE

private double balance;privat: Nur Code in der Klasse Account selbst kommt an balance heran.
public double getBalance()der Getter: gibt den Saldo zurück, ändert aber nichts.
public void deposit(double amount)ändert den Saldo. Von außen ist das der einzige Weg, den Saldo zu ändern.
if (amount > 0)die Prüfung: Nur ein positiver Betrag kommt durch. Das ist das if aus Kapitel 6 an ihrem wichtigsten Einsatzort.

Merk dir das

Attribute private, Zugriff nur über Methoden. Die Methode prüft den neuen Wert und fängt ungültige Werte ab, bevor sie ein Attribut ändert.

Level-Up: Warum der Aufwand mit Gettern und Settern?optional

Drei Gründe aus echten Projekten:

  1. Validierung: Der Setter kann Unsinn abweisen (negative Einzahlung, Age = -5, Laune = „exploding“).
  2. Kontrolle: Du kannst Attribute nur-lesbar machen: Getter ja, Setter nein. Von außen unveränderbar.
  3. Flexibilität: Du kannst das Innere der Klasse später umbauen. Wer sie benutzt, merkt nichts und ruft weiter nur getBalance() auf.

Kurz: Ohne Kapselung darf jede Klasse ein Attribut direkt ändern. Mit Kapselung läuft jede Änderung über eine Methode, die prüft.

9.5 Referenzvariablen

In Kapitel 3 hieß es: „Eine Variable ist eine Box mit Wert drin.“ Für Zahlen stimmt das. Bei Objekten steht in der Variable nicht der Zombie, sondern nur eine Referenz auf ihn. Im Speicherbild zeichnet man sie als Pfeil. Der Zombie selbst liegt im Heap, dem Bereich des Arbeitsspeichers, in dem Java die Objekte anlegt.

AUFBAU · KLICK AUF EINEN TEIL

Klasse b = a;
Klasse c = new Klasse(Werte);

Beide Zeilen speichern eine Referenz in einer Variable, aber nur die zweite erzeugt dabei ein Objekt. Referenzen kann man also kopieren.

Klasse als Typ: etwa Zombie. Eine Variable dieses Typs speichert nie das Objekt selbst, sondern eine Referenz auf ein Objekt der Klasse. Das Objekt liegt im Heap.
b bekommt eine Kopie der Referenz aus a. Danach verweisen a und b auf dasselbe Objekt: Änderst du b.mood, liest du über a.mood den neuen Wert.
a ist eine Variable, die schon eine Referenz enthält, etwa felix. Sie selbst bleibt unverändert, nur ihre Referenz wird kopiert.
c bekommt die Referenz auf das neu erzeugte Objekt. Selbst wenn es dieselben Werte hat wie das Objekt von a, ergibt c == a den Wert false, denn == vergleicht bei Objekten Referenzen, nicht Inhalte. Deshalb vergleichst du Strings mit .equals().
new erzeugt ein neues Objekt im Heap und liefert die Referenz darauf. Nur new erzeugt Objekte, eine Zuweisung wie in der ersten Zeile nie.
Werte: die Argumente für den Konstruktor, in der Reihenfolge seiner Parameter, etwa new Zombie("Mia", "gray", "relaxed").

9.6 UML-Klassendiagramm

In Projekten und Prüfungen skizziert man Klassen als UML-Klassendiagramm: ein Kasten mit drei Bereichen für Name, Attribute und Methoden. So steht eine Klasse auf dem Papier, bevor die erste Zeile Java geschrieben ist.

AUFBAU · KLICK AUF EINEN TEIL

Klassenname
- attribut: Typ
+ Klassenname(parameter: Typ)
+ methode(parameter: Typ): Rückgabetyp

- heißt private, + heißt public. Anders als in Java steht der Typ hinter dem Namen, nach einem Doppelpunkt.

Klassenname: steht allein im obersten Bereich, etwa Zombie. Taucht er unten in der Liste noch einmal auf, ist das der Konstruktor: Er hat im UML wie in Java keinen Rückgabetyp.
Sichtbarkeit: Jede Zeile unter dem Klassennamen beginnt mit ihrem Zeichen. Üblich sind private Attribute und öffentliche Methoden, also die Datenkapselung aus 9.4. In Kapitel 10 kommt # für protected dazu.
Attribut: im mittleren Bereich, eines pro Zeile. Aus - name: String wird in Java private String name;.
Typ: der Datentyp, im UML hinter dem Namen. Beim Übersetzen in Java wandert er nach vorn: Aus age: int wird int age.
Parameter: in den Klammern, mehrere durch Kommas getrennt, jeder mit seinem Typ dahinter. Aus (name: String, age: int) wird in Java (String name, int age).
Methodenname: klein geschrieben, im unteren Bereich unter dem Konstruktor, eine Methode pro Zeile. Die runden Klammern stehen auch, wenn es keine Parameter gibt: groan().
Rückgabetyp: ganz hinten, nach dem Doppelpunkt hinter der Klammer. In Java steht er vor dem Namen: Aus + groan(): void wird public void groan().

Das reicht für jetzt

  • Klasse = Bauplan, Objekt = konkretes Exemplar. Jedes new erzeugt ein neues, unabhängiges.
  • new Zombie(…) ruft den Konstruktor: heißt wie die Klasse, kein Rückgabetyp. this.name meint das Attribut.
  • felix.name = „Name von felix“: Der Punkt greift auf Attribute und Methoden zu.
  • Methoden ohne static stehen in der Klasse und benutzen die Attribute des Objekts, an dem sie aufgerufen werden.
  • private + Getter/Setter schützen die Daten (Datenkapselung). In UML: - private, + public.
  • In der Variable steckt nur eine Referenz: b = a kopiert die Referenz, nicht das Objekt. Deshalb Strings mit .equals() vergleichen.

Checkpoint

6 Fragen zu Klassen und Objekten.

1. Klasse und Objekt, was stimmt?

Eine Klasse, beliebig viele Objekte, und jedes hat seine eigenen Attributwerte.

2. Was passiert bei Zombie mia = new Zombie("Mia", "gray", "relaxed");?

new erzeugt das Objekt, der Konstruktor setzt seine Attribute. In der Variable mia steht ab dann die Referenz auf dieses Objekt.

3. Wie liest man felix.mood?

Der Punkt-Operator = „von“. Damit greifst du auf Attribute und Methoden eines Objekts zu.

4. Woran erkennst du einen Konstruktor in einer Klasse?

Klasse Zombie → Konstruktor public Zombie(…). Kein void, kein int davor, Konstruktoren „liefern“ immer das neue Objekt.

5. Warum sollte balance im Konto private sein?

Datenkapselung: Die Methode prüft jede Änderung und weist z. B. negative Einzahlungen ab. Direktzugriff = keine Kontrolle.

6. Nach Zombie a = felix; setzt du a.mood = "wild";, was ist felix.mood?

Das Zwillings-Experiment: Ein Zombie, zwei Referenzen. Was du über die eine Variable änderst, siehst du auch über die andere.
