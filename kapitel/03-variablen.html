Variablen & Datentypen

Eine Variable kannst du dir als Box mit Etikett vorstellen: Auf dem Etikett stehen Typ und Name, in der Box liegt der Wert. Der Typ entscheidet, was hineinpasst.

ca. 55 min

DAS PROBLEM

Ein Kinoticket kostet jetzt 13 statt 12 Euro. Jemand hat das Programm angepasst. Stimmen die Preise?

Cinema.java

System.out.println("1 ticket: " + 13 + " euros");
System.out.println("2 tickets: " + 2 * 13 + " euros");
System.out.println("3 tickets: " + 3 * 12 + " euros");
KONSOLE

3 Tickets für 36 Euro? Der Preis steht dreimal im Code, und an einer Stelle wurde er vergessen.

Cinema.java

int price = 13;
System.out.println("1 ticket: " + price + " euros");
System.out.println("2 tickets: " + 2 * price + " euros");
System.out.println("3 tickets: " + 3 * price + " euros");
KONSOLE

Jetzt steht der Preis an genau einer Stelle. Ändert er sich, änderst du eine Zeile. Wie Variablen funktionieren, zeigt dieses Kapitel.

3.1 Variablen deklarieren und Werte zuweisen

Programme müssen sich Dinge merken: Punktestände, Namen, Preise. Dafür gibt es Variablen: benannte Speicherplätze für je einen Wert.

AUFBAU · KLICK AUF EINEN TEIL

Typ name = Wert;

Vorne der Typ, also welche Werte die Variable aufnehmen kann, dann ihr Name, hinter dem = der Wert. Einen neuen Wert weist du später ohne Typ zu: age = 21;.

Typ: legt fest, welche Werte die Variable speichern kann: int für ganze Zahlen, double für Kommazahlen, String für Text. Er steht nur bei der Deklaration. Schreibst du ihn vor denselben Namen ein zweites Mal, meldet der Compiler variable age is already defined.
Name: frei wählbar, beginnt mit einem Kleinbuchstaben, ohne Leerzeichen. Jedes weitere Wort beginnt groß: zombieCount. Groß- und Kleinschreibung zählt, age und Age sind zwei verschiedene Variablen.
Das Gleichheitszeichen ist der Zuweisungsoperator: Der Wert rechts wird in der Variablen links gespeichert. Deshalb steht die Variable immer links: age = 20;, nicht 20 = age;.
Wert: muss zum Typ passen, etwa 20 für int, 4.99 für double (mit Punkt, nicht mit Komma) oder "Aylin" für String. Rechts darf auch eine Rechnung stehen, etwa age + 1.
Das Semikolon beendet die Anweisung, wie jede Anweisung in Java. Fehlt es, meldet der Compiler ';' expected.

so geht's

int age = 20;
//  ^      ^
//  |      '-- der Wert, der in die Box kommt
//  '-- der Name der Box (suchst du dir aus)
//
// und ganz vorne: der TYP, was die Box aufnehmen darf

Diese eine Zeile macht drei Dinge auf einmal:

ZEILE FÜR ZEILE

intDeklaration: Java legt eine Variable für ganze Zahlen (int) an.
ageBenennung: Die Variable heißt age.
= 20;Zuweisung: Sie bekommt den Wert 20.

Merk dir das

= heißt nicht „ist gleich“, sondern „nimm den Wert rechts und speichere ihn in der Variablen links“. Deshalb ist age = age + 1; völlig okay: alten Wert lesen, 1 addieren, das Ergebnis wieder in age speichern.

Nochmal anders erklärt: eine Variable, ein Wertoptional

Jede Variable hat einen festen Typ und einen Namen, und sie speichert immer genau einen Wert.

  • int number = 20; → Java legt eine int-Variable namens number an und speichert darin die 20.
  • number = 99; → Die 99 überschreibt die 20. Eine Variable, ein Wert.
  • number = "ninety-nine"; → Ein Text passt nicht zum Typ int. Der Compiler meldet incompatible types.

Mini-Übung zum Festigen: welcher Typ passt? Füll die Lücken:

Uebung.java

 zombieCount = 12;
 brainCost = 3.49;
 isFull = false;

Zuweisungs-Rätsel: Hängen x und y zusammen?

y bekommt den Wert von x, danach ändert sich x. Hängen die beiden Variablen jetzt zusammen? Erst tippen, dann ausführen:

Kopie.java (Ausschnitt)

int x = 5;
int y = x;        // y bekommt … ja, was eigentlich genau?
x = 10;           // x ändert sich …

System.out.println(y);   // … und y?
KONSOLE
Auflösung: erst ausführen, dann aufklappen!

y bleibt bei 5: Es hat eine Kopie des Werts bekommen und hängt nicht an x. Zuweisungen kopieren Werte, keine Verbindungen. (Merk dir das: In Kapitel 9 is es anders.)

3.2 Grundlegende Datentypen

Jede Variable hat einen Typ, und der legt fest, was hineinpasst: ganze Zahlen, Kommazahlen, Ja oder Nein, ein einzelnes Zeichen oder Text. Mit diesen fünf fängst du an.

DieBigFive.java

int    points   = 1337;        // ganze Zahlen
double price    = 4.99;        // Kommazahlen (mit PUNKT, nicht Komma!)
boolean hunger  = true;        // nur true oder false
char   grade     = 'A';         // EIN einzelnes Zeichen, in 'einfachen' Quotes
String name     = "Aylin";     // Text, in "doppelten" Quotes
  • int: ganze Zahlen: Age, Punktestand, Anzahl Kaffee heute (4)
  • double: Kommazahlen: Preise, Noten, Temperaturen
  • boolean: Ja/Nein-Fragen: eingeloggt? volljährig? WLAN da?
  • char: ein einzelnes Zeichen: 'A', '?', '7'
  • String: Text beliebiger Länge: Namen, Nachrichten, Passwörter (bitte nicht im Klartext)
Level-Up: Warum schreibt man String groß?optional

int, double, boolean, char sind primitive Typen, schlichte Werte. String ist eine Klasse, ein Objekt mit eingebauten Methoden:

StringKannWas.java

String name = "Aylin";
System.out.println(name.length());   // 5, wie lang ist der Text?

Der Punkt hinter name ist ein Methodenaufruf. Die wichtigsten zeigt Kapitel 5, Klassen und Objekte Kapitel 9.

Variablen selbst befüllen

Typ wählen, Wert eintippen, zuweisen. Der Compiler prüft den Typ wie in Kapitel 1. Provozier ruhig einen Fehler!

Noch kein Wert zugewiesen.

int myValue leer*

dein Code (schreibt sich live)

int myValue;   // deklariert, aber noch leer

* Genau genommen ist sie nicht „leer“, sondern nicht initialisiert: Der Compiler lässt sie erst lesen, wenn ihr ein Wert zugewiesen wurde.

3.3 Wertebereiche der Datentypen

Jeder Typ belegt eine feste Zahl an Bytes. Was nicht hineinpasst, passt nicht. Für Zahlen jenseits von gut 2 Milliarden gibt es deshalb long.

TypGrößeWertebereich
int4 Byte−2 147 483 648 bis 2 147 483 647, knapp ±2,1 Milliarden
long8 Byterund ±9,2 Trillionen, für alles, was in kein int passt
double8 Byteriesig, dafür nicht beliebig genau
boolean1 Bittrue oder false, im Speicher meist 1 Byte
char2 Bytegenau ein Zeichen

Und an der Grenze? Passiert nichts Lautes. Genau das ist das Problem:

Limit.java

public class Limit {

    public static void main(String[] args) {
        int big = 2147483647;

        System.out.println(big);
        System.out.println(big + 1);
    }

}
KONSOLE

ZEILE FÜR ZEILE

int big = 2147483647;der größte Wert, der in ein int passt.
System.out.println(big);gibt ihn unverändert aus.
System.out.println(big + 1);Eins mehr passt nicht hinein. Java meldet nichts, der Wert kippt ans untere Ende des Bereichs: -2147483648.

Merk dir das

  • Ein int läuft bei gut 2,1 Milliarden über und kippt ins Negative: kein Absturz, keine Meldung, nur eine falsche Zahl. Ein Logikfehler (Kapitel 1).
  • Für alles, was groß werden kann, nimmt man long: Einwohnerzahlen, große Centbeträge, Zeitstempel in Millisekunden.
  • Große Zahlen im Quelltext brauchen ein L: long population = 8200000000L;. Sonst meldet der Compiler integer number too large.
Level-Up: Woher kommen die 2 147 483 647?optional

4 Byte sind 32 Bit, also 32 Schalter. Einer trägt das Vorzeichen, 31 bleiben für den Betrag: 2 hoch 31 minus 1 = 2 147 483 647. Ausgerechnet, nicht ausgedacht.

Mit den Bits kann man auch direkt arbeiten. Zwei Operatoren schieben sie:

Bits.java

public class Bits {

    public static void main(String[] args) {
        int eight = 1 << 3;
        int two = 8 >> 2;

        System.out.println(eight + " " + two);
        System.out.println(Integer.toBinaryString(10));
        System.out.println(Integer.MAX_VALUE);
    }

}
KONSOLE

1 << 3: aus 00000001 wird 00001000, also 8. Jede Stelle nach links verdoppelt, nach rechts halbiert (und schneidet ab). Im Alltag multipliziert man mit *, aber so erklärt sich, warum Speichergrößen 8, 16, 32, 64 heißen.

Level-Up: Es gibt noch mehr Zahlentypen (und einen berühmten Überlauf)optional

Alle Zahlentypen im Überblick: byte (winzig), short (klein), int (Standard), long (riesig), float (Komma, ungenauer), double (Komma, Standard).

Fun Fact: 2014 musste YouTube den Zähler von „Gangnam Style“ auf long umstellen, weil das Video die int-Grenze überschritten hat.

3.4 Konstanten mit final

Manche Werte stehen fest: Mehrwertsteuer, Höchstbelegung, Zahl der Wochentage. Eine normale Variable könnte jede Zeile überschreiben, auch aus Versehen. final verbietet das.

AUFBAU · KLICK AUF EINEN TEIL

final Typ NAME = Wert;

Eine ganz normale Deklaration, nur mit final davor.

final macht die Variable zur Konstante: Nach der ersten Zuweisung lässt sich ihr Wert nicht mehr ändern. Ein späteres VAT = 0.07; lehnt der Compiler ab.
Typ: wie bei jeder Variable, etwa double für einen Steuersatz wie 0.19 oder int für die Zahl der Wochentage.
NAME: Konstanten schreibt man ganz groß, mehrere Wörter mit Unterstrich: VAT, MAX_RESIDENTS. Der Compiler verlangt das nicht, aber so sieht man beim Lesen sofort, dass sich der Wert nicht ändert.
Wert: wird gleich bei der Deklaration zugewiesen und bleibt danach gleich. Ändert sich der Steuersatz doch einmal, änderst du ihn an genau dieser einen Stelle im Code.

eine Konstante

final double VAT = 0.19;

ZEILE FÜR ZEILE

finalmacht die Variable unveränderlich. Ein späteres VAT = 0.07; übersetzt gar nicht erst: cannot assign a value to final variable VAT.
double VAT = 0.19;sonst eine Deklaration wie jede andere: Typ, Name, Wert.

Merk dir das

Konstanten schreibt man ganz groß, Wörter mit Unterstrich: VAT, MAX_RESIDENTS (Kapitel 2). So sieht man beim Lesen sofort: Hier ändert sich nichts.

Aufgabe 3.4.1: Deklarations-Werkstatt

Schreib jede Zeile komplett: Typ, Name, =, Wert, Semikolon. Den Namen wählst du selbst. Drei der sieben haben eine Falle, genau ein Zeichen groß.

Werkstatt.java: jede Zeile komplett

// die ganze Zahl 17


// der Betrag 4,99 Euro


// ja


// das einzelne Zeichen B


// der Text Aylin


// die Zahl 8 200 000 000


// 19 Prozent Mehrwertsteuer, unveränderlich

Die drei Ein-Zeichen-Fallen
  • price: ein Punkt, kein Komma. 4,99 ist für Java keine Zahl.
  • grade: einfache Anführungszeichen. "B" wäre ein String mit einem Zeichen, kein char.
  • population: das L am Ende, sonst integer number too large.

Außerdem: true schreibt sich klein, die Konstante groß.

3.5 Arithmetische Operatoren und Ganzzahldivision

Mit Variablen rechnet Java wie ein Taschenrechner, mit einer berühmten Ausnahme beim Teilen. Und + kann mehr als rechnen: Es verkettet auch Texte, hängt sie also aneinander.

AUFBAU · KLICK AUF EINEN TEIL

a + b    a - b    a * b    a / b
a % b    Modulo: der Rest beim Teilen

10 % 3 ist 1, denn 10 = 3·3 + 1. Gerade Zahl? number % 2 == 0

a (linker Operand): eine Zahl, eine Variable oder eine Rechnung, etwa 7 oder price. Der Typ der beiden Operanden bestimmt den Typ des Ergebnisses: int mit int ergibt int, ist ein double beteiligt, ergibt es double.
b (rechter Operand): bei / und % der Teiler. Sind beide Operanden int und ist b gleich 0, bricht das Programm mit der Meldung / by zero ab.
+ (Addition) addiert zwei Zahlen. Ist einer der Operanden ein String, verkettet + stattdessen: "Points: " + 5 ergibt den Text Points: 5.
- und * subtrahieren und multiplizieren. Das Malzeichen ist in Java der Stern *, nicht x oder ·. Es gilt Punkt vor Strich: 2 + 3 * 4 ergibt 14.
/ (Division): Sind beide Operanden int, ist auch das Ergebnis ein int. Die Nachkommastellen werden abgeschnitten, nicht gerundet: 7 / 2 ergibt 3, erst 7.0 / 2 ergibt 3.5.
% (Modulo) liefert den Rest der ganzzahligen Division: 7 % 2 ergibt 1, 12 % 4 ergibt 0. Damit prüfst du, ob eine Zahl durch eine andere teilbar ist: Dann ist der Rest 0.

Und jetzt halt dich fest:

Surprise.java

public class Surprise {

    public static void main(String[] args) {
        System.out.println(7 / 2);      // int / int   ???
        System.out.println(7 % 2);      // der Rest beim Teilen
        System.out.println(7.0 / 2);    // double im Spiel  ???
    }

}
KONSOLE
Auflösung: erst ausführen, dann aufklappen!

7 / 2 ergibt 3, nicht 3,5. Teilen sich zwei ints, wird das Komma abgehackt, nicht gerundet. Ist eine Kommazahl beteiligt (7.0 / 2), rechnet Java „richtig“. Diese Falle kostet weltweit jedes Jahr tausende Stunden Fehlersuche.

+ verkettet auch Texte:

Verketten.java

String name = "Aylin";
int age = 20;
System.out.println(name + " is " + age + " years old.");
KONSOLE

Damit hat + zwei Aufgaben, rechnen und verketten. Java entscheidet von links nach rechts. In Prüfungen sehr beliebt:

PlusZwilling.java (Ausschnitt)

System.out.println(1 + 1);         // Zahl + Zahl
System.out.println("1" + 1);       // Text + Zahl
System.out.println(1 + 1 + "1");   // ???
System.out.println("1" + 1 + 1);   // ???
KONSOLE
Auflösung: erst ausführen, dann aufklappen!

2, 11, 21, 111. Sobald Text im Spiel ist, verkettet +, und ab da alles Weitere auch. Steht die Rechnung vor dem Text (1 + 1 + "1"), wird erst gerechnet (2), dann verkettet (21).

Merk dir das

  • Falle 1: int / int hackt das Komma ab, es wird nicht gerundet.
  • Falle 2: Hängt Text am +, wird verkettet statt gerechnet.

3.6 Typumwandlung (Casting)

Zurück zur Falle: 7 / 2 ergibt 3, weil beide Zahlen int sind. Die Rettung heißt Casting: Zieltyp in Klammern vor den Wert, und Java rechnet in diesem Typ weiter.

AUFBAU · KLICK AUF EINEN TEIL

(Zieltyp) Wert

Casting macht aus Zahl Zahl. Aus Text eine Zahl machen ("17" von der Tastatur) heißt Parsen: Kapitel 5.

Die runden Klammern um den Zieltyp machen ihn zum Cast-Operator. Sie sind Pflicht: (int) price, nicht int price.
Zieltyp: der Typ, den der Wert danach haben soll, etwa int oder double. Von double nach int werden die Nachkommastellen abgeschnitten, nicht gerundet: (int) 4.99 ergibt 4.
Wert: eine Zahl, eine Variable oder eine Rechnung. Der Cast gilt nur für den Wert direkt dahinter: (double) 7 / 2 ergibt 3.5, (double) (7 / 2) dagegen 3.0.

Casting.java

double price = 4.99;
int rough = (int) price;        //  4 (abgeschnitten, nicht gerundet!)

int a = 7;
double exact = a;              //  7.0 (geht automatisch, verliert nichts)

double correct = (double) 7 / 2;   //  3.5 (so rettest du die Division!)

ZEILE FÜR ZEILE

(int) pricemacht aus 4.99 ein int: 4. Die Nachkommastellen werden abgeschnitten, nicht gerundet.
double exact = a;Klein nach groß geht von selbst: Aus der 7 in a wird 7.0, nichts geht verloren.
(double) 7 / 2Erst wird die 7 zur 7.0, dann wird mit Komma geteilt: 3.5.

Merk dir das

  • Klein nach groß (int → double): macht Java automatisch, nichts geht verloren.
  • Groß nach klein (double → int): nur mit (int), die Nachkommastellen fallen weg, abgeschnitten, nicht gerundet.

Der Cast gilt nur für den Wert direkt dahinter:

  • (double) 7 / 2: aus 7 wird 7.0, dann wird mit Komma geteilt. Ergebnis 3.5.
  • (double) (7 / 2): erst int-Division, dann Cast. Ergebnis 3.0, die Nachkommastelle war schon weg.

3.7 Zuweisungsoperatoren und Operatorrangfolge

Aufsummieren, herunterzählen, doubleIt: Das kommt so oft vor, dass Java dafür Kurzformen hat. Und stehen mehrere Operatoren in einer Zeile, entscheidet die Rangfolge, was zuerst gerechnet wird.

Diese Kurzformen begegnen dir ab jetzt überall:

Kurzformheißt ausgeschriebentypisch für
points += 5points = points + 5aufsummieren
life -= 1life = life - 1herunterzählen
price *= 2price = price * 2doubleIt
i++i = i + 1den Zähler einer Schleife (Kapitel 7)
i--i = i - 1rückwärts zählen

Ein Unterschied: Kurzformen casten stillschweigend. x += 2.7; klappt bei int x = 5; und ergibt 7, x = x + 2.7; lehnt der Compiler ab. Genauso wird mit c++ aus 'A' ein 'B'.

Bei ++ zählt außerdem, ob es vor oder hinter der Variablen steht. Sag die Ausgabe voraus:

Shorthand.java

public class Shorthand {

    public static void main(String[] args) {
        int points = 10;
        points += 5;
        System.out.println(points);

        int i = 3;
        System.out.println(i++);
        System.out.println(i);
        System.out.println(++i);
    }

}
KONSOLE

ZEILE FÜR ZEILE

points += 5;kurz für points = points + 5: Aus 10 wird 15.
System.out.println(i++);Postform: gibt den alten Wert 3 aus und erhöht danach auf 4.
System.out.println(i);zeigt die 4.
System.out.println(++i);Präform: erhöht zuerst auf 5 und gibt dann die 5 aus.

Merk dir das

  • i++ (Postform): gibt den alten Wert heraus, erhöht danach.
  • ++i (Präform): erhöht zuerst, gibt den neuen Wert heraus.
  • Steht es allein in einer Zeile, ist es egal. Deshalb schreibt man in Schleifen einfach i++.

Mehrere Operatoren in einer Zeile? Es gilt die Rangfolge aus Mathe:

  1. Klammern ( ) zuerst
  2. Punktrechnung * / %
  3. Strichrechnung + -
  4. Zuweisung = ganz zum Schluss

Also ist 2 + 3 * 4 gleich 14, nicht 20. Wer unsicher ist, klammert: kostet nichts, spart Diskussionen.

3.8 Ausgabe verschiedener Datentypen

Fünf Typen, ein Befehl zum Anzeigen: println erkennt den Typ selbst und macht Text daraus.

Erst du, dann Java

Fünf Variablen, fünf Ausgaben. Schreib auf, was die Konsole zeigt, bevor du ausführst. Bei der zweiten Zeile lohnt sich eine Wette.

Printing.java

public class Printing {

    public static void main(String[] args) {
        int age = 3;
        double weight = 4;
        boolean infected = true;
        char zone = 'B';
        String name = "Zombiefelix";

        System.out.println(age);
        System.out.println(weight);
        System.out.println(infected);
        System.out.println(zone);
        System.out.println(name);
    }

}
KONSOLE
Auflösung: erst ausführen, dann aufklappen!
  • double weight = 4; zeigt 4.0: Ein double hat immer eine Nachkommastelle.
  • B und Zombiefelix erscheinen ohne Hochkommas und Anführungszeichen. Die gehören zum Quelltext, nicht zum Wert.

Merk dir das

println zeigt den Wert, nicht den Quelltext. Anführungszeichen gehören zum Quelltext: Sie zeigen dem Compiler, wo ein Text anfängt und aufhört.

Bei einem Typ lohnt sich ein zweiter Blick: char ist Zeichen und Zahl zugleich. Rate wieder mit:

ZeichenOderZahl.java (Ausschnitt)

char zone = 'B';
System.out.println(zone);             // ?
System.out.println(zone + 1);         // ???
System.out.println("Zone " + zone);   // ?
KONSOLE
Auflösung: was ist da passiert?

Intern ist ein char eine Zahl: 'B' ist 66. Rechnest du damit, rechnet Java: 67, nicht C. Kommt Text dazu, verkettet +. Text im Spiel → verkettet. Sonst gerechnet.

Schau, was du seit Kapitel 2 tippst: Name, Klammern, Wert dazwischen, println(age). So ruft man eine Methode auf. println hat jemand anderes geschrieben. Im nächsten Kapitel baust du deine erste eigene.

Das reicht für jetzt

  • Variable = Speicherplatz mit Typ, Name und Wert. = ist eine Zuweisung, kein „ist gleich“.
  • int ganze Zahl · double Kommazahl (Punkt!) · boolean true/false · char ein Zeichen · String Text
  • Zuweisungen kopieren Werte. final macht eine Variable zur Konstante.
  • int läuft bei 2,1 Milliarden über, für Großes long.
  • Falle 1: int / int hackt das Komma ab. Rettung: (double) 7 / 2.
  • Falle 2: Hängt Text am +, wird verkettet statt gerechnet.

Checkpoint

5 Fragen: Nummer 4 ist die Falle aus diesem Kapitel.

1. Welcher Typ passt für den Preis 2.50 €?

Kommazahl → double. Einer int-Variablen kann man 2.50 gar nicht zuweisen.

2. Was macht diese Zeile? points = points + 10;

= heißt „nimm den Wert rechts und speichere ihn links“: alten Wert lesen, 10 addieren, Ergebnis wieder in points speichern. In Mathe illegal, in Java Alltag.

3. Welche Deklaration ist korrekt?

char nimmt EIN Zeichen in einfachen Quotes. boolean nimmt nur true/false (ohne Anführungszeichen), String braucht doppelte Quotes.

4. Was gibt System.out.println(9 / 2); aus?

int / int → Komma wird abgehackt (nicht gerundet!). 9 / 2 = 4 Rest 1. Für 4.5 bräuchtest du z. B. 9.0 / 2.

5. Was ergibt 10 % 3?

% ist der Rest beim Teilen: 10 = 3·3 + 1. Praktisch z. B. um zu prüfen, ob eine Zahl gerade ist: number % 2 == 0.
